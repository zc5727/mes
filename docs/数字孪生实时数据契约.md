# 数字孪生实时数据契约

- 适用端：NestJS REST/MQTT 采集、数字孪生前端、后续 WebSocket 推送
- 目标：同一设备、产线和告警在 MQTT、后端、前端中使用同一组身份和时间字段
- 当前状态：目标契约已冻结；后端已提供数字孪生快照投影，但仍有兼容字段和待补齐字段，见第 6 节

## 1. 统一原则

1. `lineId`、`deviceId`、`alarmId` 是跨系统稳定业务标识，禁止用展示名称替代。
2. `timestamp` 表示事件/遥测产生时间；`lastUpdatedAt` 表示该实体状态最后一次被系统接受的时间。
3. 所有时间使用 ISO 8601 UTC 字符串，例如 `2026-08-29T09:00:00.000Z`。
4. `metrics` 必须是结构化对象，数值单位由字段名或 `metricDefinitions` 说明，禁止前端猜测单位。
5. `position` 使用 `{ x, y, z }`，坐标系和单位必须由场景配置固定；后端没有可靠位置时返回 `null`，不得伪造坐标。
6. `snapshotVersion` 用于判断快照新旧；同一租户、同一实体只接受不早于当前版本/时间的更新。
7. `dataSource` 用于区分 `simulator`、`mqtt`、`database`、`mock`，前端必须展示或至少在调试信息中保留来源。
8. 租户隔离由请求上下文和消息 topic 同时保证，契约字段本身不替代权限校验。

## 2. 冻结字段定义

| 字段 | 类型 | 必填 | 适用对象 | 约束 |
|---|---|---:|---|---|
| `lineId` | `string` | 是 | 产线、设备、告警、AGV、工单关联 | 稳定 ID；推荐使用 `line-cnc` 这类 canonical ID |
| `deviceId` | `string` | 设备/设备告警必填 | 设备、遥测、设备告警 | 稳定设备 ID；不可混用展示 code |
| `alarmId` | `string` | 告警必填 | 告警事件、告警状态 | 同一告警生命周期保持不变 |
| `timestamp` | `string` | 是 | 事件、遥测、快照 | ISO 8601 UTC；事件发生时间 |
| `metrics` | `object` | 是 | 设备、产线、AGV、快照 | JSON 对象；字段值需为可序列化标量或结构化指标 |
| `position` | `{x,y,z}` 或 `null` | 是 | 设备、AGV、场景对象 | 数字坐标；没有可信位置时为 `null` |
| `snapshotVersion` | `string` | 是 | 快照、实时更新 | 单调版本或可比较版本；推荐 `tenantId + sequence` |
| `dataSource` | `'simulator' \| 'mqtt' \| 'database' \| 'mock'` | 是 | 所有实时数据 | 标识事实来源，不代表数据质量 |
| `lastUpdatedAt` | `string` | 是 | 状态实体、快照 | ISO 8601 UTC；系统接受该状态的时间 |

## 3. MQTT 到数字孪生的字段映射

| 来源 | 当前字段 | 目标字段 | 处理要求 |
|---|---|---|---|
| telemetry topic | topic 中 tenant/line/device | `lineId`、`deviceId` | topic 身份必须与 payload 一致 |
| telemetry payload | `timestamp` | `timestamp` | 保留原始设备产生时间 |
| telemetry payload | 分散的温度、节拍、计数 | `metrics` | 后端规范化，不由前端猜测 |
| ingestion | `receivedAt` | `lastUpdatedAt` | 系统接受时间 |
| ingestion | 无版本字段 | `snapshotVersion` | 后端生成单调版本 |
| ingestion | topic 来源 | `dataSource=mqtt` | 禁止前端默认为 mock |
| alarm payload | `id` | `alarmId` | 后端输出统一为 `alarmId`；兼容输入只在适配层转换 |
| alarm payload | `startedAt` | `timestamp` | created 事件发生时间 |
| alarm payload | `clearedAt` | `clearedAt` | cleared 事件必填 |

正式 MQTT topic：

```text
mes/simulator/{tenantId}/lines/{lineId}/devices/{deviceId}/telemetry
mes/simulator/{tenantId}/alarms
```

## 4. REST/实时推送要求

当前数字孪生专用查询入口：

```text
GET /api/v1/digital-twin/snapshot
GET /api/v1/digital-twin/current-state
```

响应外层为 `{ data, tenantId }`。`/dashboard/*` 继续承担运营看板聚合，不替代数字孪生快照契约。

### 必须由后端提供

设备、产线、告警和快照相关 API/推送至少要提供：

- `lineId`
- `deviceId`（设备及设备告警）
- `alarmId`（告警）
- `timestamp`
- `lastUpdatedAt`
- `metrics`
- `position` 或明确的 `null`
- `snapshotVersion`
- `dataSource`
- 租户上下文 `tenantId`（响应元数据或受控请求上下文）

此外还必须提供：

- 设备/产线/告警状态。
- 告警级别、消息、active/cleared 生命周期。
- snapshot 的组成范围和生成时间。
- 数据是否来自实时缓存、数据库还是 mock 的可观测标识。
- 乱序和重复更新的处理结果或可观察日志。

### 前端使用要求

- 不再用 `id` 同时表示设备 ID和告警 ID；渲染层可保留内部 UI id，但适配层必须明确映射。
- 不再根据数组下标长期生成设备位置；真实位置优先，缺失时使用场景配置并标记为 `positionSource=scene-default`。
- 不把 `observedAt`、`time` 当作统一时间字段直接跨对象复用；适配层映射为 `timestamp`/`lastUpdatedAt`。
- `dataSource=mock` 或 REST 降级时显示“演示/降级”状态。
- 收到低于当前 `snapshotVersion` 或 `lastUpdatedAt` 的事件时不得回退画面状态。

## 5. 版本和一致性规则

1. `snapshotVersion` 在同一租户内单调递增；不同租户之间不比较。
2. 单实体更新比较顺序：先比较 `snapshotVersion`，版本相同再比较 `timestamp`，仍相同视为重复。
3. 设备状态更新必须以 `lineId + deviceId` 为键；告警状态必须以 `tenantId + alarmId` 为键。
4. `alarm.cleared` 到达后，告警从 active 视图移除，但事件历史必须保留。
5. WebSocket 断线重连后必须先发送完整 snapshot，再发送增量事件。
6. REST 快照与 WebSocket 快照应使用同一字段命名和同一 ID 映射。
7. 任何跨租户、跨产线、跨设备的 ID 不一致都视为契约错误，不允许在前端静默修正。

## 6. 当前代码差异

### 已具备

- MQTT topic 已包含租户、产线、设备身份。
- MQTT parser 已校验 telemetry/alarm payload 和 topic 身份。
- `DeviceTelemetryCache` 已按租户、产线、设备缓存并拒绝重复/过期 telemetry。
- 告警去重已按租户和告警 ID处理 created/cleared。
- 前端已有 `position`、设备/产线/告警基础类型和实时消息解析器。
- 后端已有数字孪生快照投影，并以 `canonicalId/sourceId` 兼容台账 ID 与模拟器原始 ID。

### 必须由后端补齐

1. REST 和 WebSocket 输出统一使用 `alarmId`，不要只返回 `id`。
2. 设备、产线、告警、快照统一补充 `snapshotVersion`、`dataSource`、`lastUpdatedAt`。
3. 把 MQTT 分散 telemetry 字段规范化为 `metrics`，并定义单位。
4. 为设备、AGV和告警提供可信 `position` 或显式 `null`。
5. 冻结 ID 兼容规则：对外统一 `deviceId`，内部可保留 `canonicalId`；`sourceId` 仅表示模拟器/网关原始 ID，禁止前端自行猜测转换。
6. 冻结产线规则：对外 `lineId` 使用 canonical ID；展示 code（如 `LINE-01`）单独作为 `lineCode`，不能替代 `lineId`。
7. 提供 snapshotVersion 生成、比较和持久化规则。
8. 数据库接入后保留 `timestamp` 与 `lastUpdatedAt`，不能用查询时间覆盖事件时间。
9. 增加告警历史和 cleared 事件查询，不能只返回 active 列表。
10. 完成 MQTT→WebSocket 推送前，前端只能把 REST 刷新视为实时性来源。
