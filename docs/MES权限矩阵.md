# MES 权限矩阵

**版本：** v1.1
**适用范围：** 核心 MES 试点版，单工厂、四条产线  
**设计原则：** 最小权限、数据范围隔离、关键动作确认、全量审计

> 本文保留为权限细则；用户角色、菜单树、功能域路线和端到端验收的统一入口为 `docs/MES成熟功能域路线与端到端验收.md`。

**当前基线：** 提交 `9d9633d4`。矩阵中的“执行”仅表示授权设计，不表示真实设备控制已接入；仿真故障注入与真实设备写入必须使用不同接口、凭据和环境。

## 1. 角色定义

| 角色 | 定位 | 默认数据范围 |
|---|---|---|
| 系统管理员 | 系统配置、账号、角色、运行维护 | 全工厂，但不能替代业务审批 |
| 厂长 | 全局经营和生产决策 | 全工厂只读；关键动作审批 |
| 生产主管 | 计划、工单、产线执行 | 所属车间及产线 |
| 设备主管 | 设备、维护、故障处理 | 所属车间设备 |
| 质量主管 | 检验、质量、批次和图纸确认 | 所属车间质量对象 |
| 班组长 | 班组任务、报工、点检和异常 | 所属班组产线 |
| 操作员 | 执行工单、报工、填报现场数据 | 被分配的设备和工单 |
| 审计/观察员 | 查询和审计 | 被授权范围只读 |

## 4. 高风险动作控制

以下动作必须经过后端授权、二次确认和审计，不能由前端按钮直接绕过：

| 动作 | 发起角色 | 审批角色 | 是否允许智能体直接执行 |
|---|---|---|---|
| 真实设备启停 | 设备主管 | 厂长或授权生产主管 | 否 |
| 产线停线 | 生产主管/设备主管 | 厂长 | 否 |
| 批次锁定 | 质量主管/生产主管 | 质量主管 | 否 |
| 批次放行 | 质量主管 | 厂长或质量负责人 | 否 |
| 工单跨线转移 | 生产主管 | 厂长或授权生产主管 | 否 |
| 工艺参数修改 | 设备主管/质量主管 | 质量主管 | 否 |
| 图纸正式发布 | 工程/质量人员 | 质量主管 | 否 |
| 策略方案执行 | 生产主管/设备主管 | 厂长 | 否 |
| 仿真故障注入 | 设备主管/生产主管 | 无，限仿真环境 | 只允许调用仿真工具 |

## 5. API 鉴权要求

每个请求至少包含：

```json
{
  "userId": "user-001",
  "role": "production_supervisor",
  "factoryId": "factory-demo",
  "scope": ["workshop-01", "line-cnc"],
  "sessionId": "session-001",
  "traceId": "trace-001"
}
```

后端必须执行：

1. 身份认证。
2. 角色权限判断。
3. 工厂、车间、产线、设备和工单范围判断。
4. 高风险动作的审批状态判断。
5. 幂等键和重复请求判断。
6. 审计记录写入。

前端隐藏按钮不等于权限控制，所有权限必须在后端再次校验。

## 6. 审计字段

所有编辑、审批和执行动作至少记录：

```text
auditId
userId
role
factoryId
resourceType
resourceId
action
beforeValue
afterValue
reason
approvalId
sessionId
traceId
result
createdAt
```

禁止把密码、访问令牌和完整敏感附件内容写入日志。

## 7. 智能秘书权限边界

智能秘书只能代表当前登录用户调用其有权访问的工具：

- 查询类工具：继承用户的数据范围。
- 分析类工具：只读取授权数据。
- 建议类工具：可以生成方案，但不能改变生产状态。
- 创建草稿：可以创建工单、点检或审批草稿。
- 执行类工具：必须返回审批请求，不能直接执行高风险动作。

工具调用必须携带 `userId`、`role`、`scope`、`sessionId` 和 `traceId`，并写入审计日志。

## 8. 实施顺序

1. 先实现后端统一 `AuthContext` 和数据范围校验。
2. 再实现功能权限常量和权限守卫。
3. 再接入产线、设备、工单和告警 API。
4. 再补审批状态机和高风险动作拦截。
5. 最后接入智能秘书工具调用。

当前核心原则：

> **厂长少按钮，但权限不能少；前端交互可以简化，后端控制必须严格。**
