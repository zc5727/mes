# 数字孪生交互问题最终验收清单

- 范围：数字孪生页面、CSS 布局、Three.js 场景控制、数据加载和控件禁用逻辑
- 排除：Nanobot、业务核心重写、真实设备控制
- 结论规则：P0/P1 未关闭不得冻结；P2 可带已知问题冻结，但必须记录后续版本

## 1. 当前交互基线

### 数据模式

- 默认 VITE_DATA_MODE=api。
- API 模式首先加载 REST；失败时保留空数据和错误提示，不会自动切换本地随机模拟。
- 只有显式设置 VITE_DATA_MODE=local 才启用浏览器本地模拟器和故障注入。
- API 模式的本地故障注入、恢复设备控件必须 disabled；这是安全边界，不是 CSS 或按钮失效。
- 未配置 VITE_REALTIME_URL 时，前端采用 REST polling，不得显示 WebSocket 已连接。

### 交互主链路

REST 首次快照 → 产线选择 → 设备/告警/AGV 过滤 → Three.js 场景同步 → 点击设备 → 左侧列表/三维浮层/右侧详情联动。

## 3. CSS 层最终验收

### 1920×1080 大屏基线

- 左侧导航、中央三维场景、右侧详情、底部日志无重叠。
- 设备/告警列表超出区域时可滚动，页面整体不出现横向滚动条。
- loading、空数据、错误 banner 均可见且不遮挡主要操作。
- disabled 控件有明确灰度和鼠标状态，不能与可操作按钮视觉混淆。
- 弹层、按钮和列表不被三维 canvas 覆盖；点击列表仍能选中设备。

### 1366×768 兼容检查

- 不要求保持全部大屏信息密度，但不得截断关键状态、产线选择和错误提示。
- 如发生面板遮挡，标记为 P2 CSS 问题，不通过修改业务数据规避。

## 4. Three.js 控制器最终验收

- 设备状态映射：running=绿色、warning=黄色、error=红色、offline=灰色。
- hover 和 selected 的放大/发光状态可恢复，不影响其他设备。
- 点击设备根节点或其子 Mesh 均能返回同一业务设备。
- 产线切换后，隐藏设备不可被射线选中。
- 新增设备能创建场景对象；已有设备更新状态和位置。
- AGV 的 moving/loading/charging/error 状态与位置/进度不互相覆盖错误。
- 页面卸载后停止动画、移除事件监听并释放 renderer、geometry、material。
- WebGL 不可用时页面至少保留 REST 状态和错误提示，不得白屏无反馈。

## 5. 数据加载与 disabled 最终验收

| 场景 | 预期 |
|---|---|
| API 可用、MQTT 可用 | 显示 API 数据；轮询或已接通 WS；数据源明确 |
| API 可用、实时 WS 未配置 | 显示 API 数据和 polling；不宣称实时 WS |
| API 不可用、VITE_DATA_MODE=api | 显示空数据/错误 banner；控制按钮 disabled；不伪造模拟数据 |
| VITE_DATA_MODE=local | 启用本地模拟数据；故障注入和恢复控件可操作 |
| API 恢复 | 自动刷新成功后清除错误，更新数据源和连接状态 |
| 旧数据到达 | 低版本/旧时间戳不得覆盖新状态 |
| 租户不一致 | 请求和 MQTT topic 不匹配时不得混入页面 |

## 7. 冻结结论

当前可以冻结：

- API 模式只读数字孪生展示。
- local 模式浏览器演示和故障注入。
- Three.js 设备点击、状态颜色、产线过滤和资源释放。
- 无后端实时 WS 时采用 REST polling 的明确降级行为。

当前不能通过最终冻结门禁：

- 前端 build 当前失败，待数字孪生前端代理修复 P0-02。
- 浏览器 I01-I12 尚未完成现场记录。

当前不能冻结为生产交付：

- 后端 MQTT 到浏览器的实时推送。
- 统一 deviceId/alarmId/snapshotVersion/dataSource/lastUpdatedAt 完整字段。
- 真实设备位置从后端到三维场景的全链路。
- 窄屏响应式布局和生产级错误恢复。

冻结前必须保留：前端 build、入口 smoke、浏览器矩阵截图、API 响应、MQTT 故障日志和已知问题清单。
