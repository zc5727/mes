# 数字孪生交互问题最终验收清单

- 范围：数字孪生页面、CSS 布局、Three.js 场景控制、数据加载和控件禁用逻辑
- 排除：Nanobot、业务核心重写、真实设备控制
- 结论规则：P0/P1 未关闭不得冻结；P2 可带已知问题冻结，但必须记录后续版本

## 1. 当前交互基线

### 数据模式

- 默认 VITE_DATA_MODE=api。
- API 模式首先加载 REST；失败时保留空数据和错误提示，不会自动切换本地随机模拟。
- 只有显式设置 VITE_DATA_MODE=local 才启用浏览器本地模拟器和故障注入。
- API 模式的故障注入、恢复设备通过后端 simulator/control 接口执行；生产环境必须由后端权限和环境策略拒绝，不能把前端 disabled 当作安全边界。
- 未配置 VITE_REALTIME_URL 时，前端采用 REST polling，不得显示 WebSocket 已连接。
- 控制模式必须明确区分 local demo、API read-only 和 approved control；模式切换不能默默改变权限。
- API 故障注入只能进入测试/演示环境，生产环境必须隐藏或拒绝。

### 交互主链路

REST 首次快照 → 产线选择 → 设备/告警/AGV 过滤 → Three.js 场景同步 → 点击设备 → 左侧列表/三维浮层/右侧详情联动。

## 3. CSS 层最终验收

### 1920×1080 大屏基线

- 左侧导航、中央三维场景、右侧详情、底部日志无重叠。
- 设备/告警列表超出区域时可滚动，页面整体不出现横向滚动条。
- loading、空数据、错误 banner 均可见且不遮挡主要操作。
- disabled 控件有明确灰度和鼠标状态，不能与可操作按钮视觉混淆。
- 弹层、按钮和列表不被三维 canvas 覆盖；点击列表仍能选中设备。

### 1366×768 兼容检查

- 不要求保持全部大屏信息密度，但不得截断关键状态、产线选择和错误提示。
- 如发生面板遮挡，标记为 P2 CSS 问题，不通过修改业务数据规避。

## 4. Three.js 控制器最终验收

- 设备状态映射：running=绿色、warning=黄色、error=红色、offline=灰色。
- hover 和 selected 的放大/发光状态可恢复，不影响其他设备。
- 点击设备根节点或其子 Mesh 均能返回同一业务设备。
- 产线切换后，隐藏设备不可被射线选中。
- 新增设备能创建场景对象；已有设备更新状态和位置。
- AGV 的 moving/loading/charging/error 状态与位置/进度不互相覆盖错误。
- 页面卸载后停止动画、移除事件监听并释放 renderer、geometry、material。
- WebGL 不可用时页面至少保留 REST 状态和错误提示，不得白屏无反馈。

## 5. 数据加载与 disabled 最终验收

| 场景 | 预期 |
|---|---|
| API 可用、MQTT 可用 | 显示 API 数据；轮询或已接通 WS；数据源明确 |
| API 可用、实时 WS 未配置 | 显示 API 数据和 polling；不宣称实时 WS |
| API 不可用、VITE_DATA_MODE=api | 显示空数据/错误 banner；控制按钮 disabled；不伪造模拟数据 |
| VITE_DATA_MODE=local | 启用本地模拟数据；故障注入和恢复控件可操作 |
| API 恢复 | 自动刷新成功后清除错误，更新数据源和连接状态 |
| 旧数据到达 | 低版本/旧时间戳不得覆盖新状态 |
| 租户不一致 | 请求和 MQTT topic 不匹配时不得混入页面 |

## 7. 控制模式与操作治理

### 7.1 控制模式

| 模式 | 可用范围 | 允许动作 | 禁止动作 |
|---|---|---|---|
| local demo | 本地演示包 | 本地故障注入、恢复、暂停模拟 | 真实设备控制、生产 API |
| API read-only | 测试/生产 | 查询、筛选、查看详情、刷新 | 故障注入、停线、复位、删除 |
| API test-control | 仅测试环境 | 受限 API 故障注入、模拟器控制 | 真实 PLC 写入、自动策略执行 |
| approved control | 未来生产能力 | 经审批的单次控制动作 | 绕过审批、批量无确认执行 |

模式切换要求：

1. 页面显示当前模式、环境、租户和数据来源。
2. 模式由服务端配置/签名配置决定，前端选择不能提升权限。
3. 从高权限模式切换到低权限模式必须清理旧控制状态和待执行动作。
4. 模式切换记录操作人、原模式、新模式、时间、原因和 traceId。

### 7.2 API 故障注入

API 故障注入必须是测试能力，不得复用真实设备控制接口：

- 请求必须包含 `tenantId`、目标 `lineId/deviceId`、故障类型、持续时间、`requestedBy` 和 `traceId`。
- 后端校验环境为 test/demo、用户具备故障演练权限、目标属于当前租户。
- 前端操作前显示影响对象、故障类型和自动恢复时间，并要求二次确认。
- 操作结果必须显示 requestId/traceId 和成功、拒绝或超时状态。
- 生产环境返回明确的 `FEATURE_DISABLED` 或 `FORBIDDEN`，不允许静默执行。

### 7.3 新增产线

新增产线操作必须同时校验：

- 唯一 `lineId`、展示 `lineCode`、名称、车间和状态。
- 产线与工厂/租户归属。
- 设备绑定、设备位置或显式空位置策略。
- 前端列表、筛选、三维可见对象、告警和看板聚合。
- 创建成功后的返回对象和 `snapshotVersion`。

新增、编辑、停用产线均需要确认；停用有设备或工单时必须显示影响清单并拒绝无依据的强制操作。

### 7.4 按钮交互标准

- 每个按钮必须有明确的 enabled、disabled、loading、success、error 状态。
- disabled 必须有原因提示，不能只降低透明度。
- 会改变状态、注入故障、删除、关闭告警或提交控制的按钮必须二次确认。
- 提交期间防重复点击；请求失败后恢复可重试状态。
- 所有结果必须更新页面状态或显示可定位错误，不允许只写 console。
- 纯查询按钮可以直接执行，但必须显示加载状态。

## 8. 确认、权限与审计要求

### 操作确认级别

| 级别 | 示例 | 要求 |
|---|---|---|
| C0 查询 | 刷新、切换产线、查看详情 | 不需要二次确认，记录访问日志可选 |
| C1 测试动作 | API 故障注入、模拟器暂停/恢复 | 显示影响对象和持续时间，二次确认 |
| C2 状态变更 | 新增/编辑/停用产线、关闭告警 | 二次确认，输入原因，提交后可追踪 |
| C3 生产控制 | 停线、复位、设备写入 | 独立权限、审批、二次确认、审计和回滚；当前版本禁止 |

### 最小权限

- `viewer`：只读查询和看板浏览。
- `operator`：C1 测试动作和受限业务操作。
- `engineer`：配置和产线维护，不能直接执行生产控制。
- `supervisor`：审批 C3 动作，不能绕过审计。
- `admin`：账号、权限和环境配置，不自动拥有设备控制权限。

权限判断必须在后端执行；前端 disabled 只是体验层，不是安全边界。

### 审计字段

所有 C1-C3 操作至少记录：

```text
auditId, tenantId, requestedBy, role, action, targetType, targetId,
before, after, reason, confirmationId, traceId, result, errorCode,
createdAt, completedAt, clientVersion, environment
```

审计日志禁止记录密码、token 和完整敏感 payload；日志必须可按租户、操作者、对象、时间和 traceId 查询。

### 通过标准

- 未授权用户无法通过改前端状态、直接调用 API 或修改请求头执行受限动作。
- 所有 C1-C3 操作都能查到审计记录和结果。
- 重复提交不会生成重复控制动作。
- 失败、拒绝、超时和取消均有明确结果。
- 生产模式下 API 故障注入、local simulator 和真实控制入口均按环境策略处理。

## 9. 冻结结论

当前可以冻结：

- API 模式只读数字孪生展示。
- local 模式浏览器演示和故障注入。
- Three.js 设备点击、状态颜色、产线过滤和资源释放。
- 无后端实时 WS 时采用 REST polling 的明确降级行为。

当前不能通过最终冻结门禁：

- 浏览器 I01-I18 尚未完成现场记录。
- P0-02 已关闭，但关闭依据是代码和构建输出，不是现场交互记录。

当前不能冻结为生产交付：

- 后端 MQTT 到浏览器的实时推送。
- 统一 deviceId/alarmId/snapshotVersion/dataSource/lastUpdatedAt 完整字段。
- 真实设备位置从后端到三维场景的全链路。
- 窄屏响应式布局和生产级错误恢复。

冻结前必须保留：前端 build、入口 smoke、浏览器矩阵截图、API 响应、MQTT 故障日志和已知问题清单。
