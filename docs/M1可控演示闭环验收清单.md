# M1 可控演示闭环验收清单

## 1. 范围冻结

M1 只验收以下闭环：

1. 所有关键按钮可操作或按权限正确 disabled。
2. API 模式与本地模式可明确切换。
3. 按设备进行故障注入和恢复。
4. 产线创建、查询、修改、状态变更和删除。
5. 故障 → 告警 → 看板高亮 → 恢复。
6. 演示过程可重复、可观察、可回退。

M1 不包含：

- Nanobot。
- SaaS、多租户计费。
- 真实 PLC 写入。
- 自动停线和自动策略执行。
- PostgreSQL 生产级持久化。
- Tauri 生产签名和自动更新。

## 4. 设备故障闭环

### 4.1 Local 模式

操作：

1. 设置 VITE_DATA_MODE=local。
2. 选择设备。
3. 选择 OVERHEAT、JAM 或 COMMUNICATION_LOSS。
4. 点击注入故障。
5. 确认状态变化。
6. 点击恢复设备。

预期：

- 设备状态变为 error。
- 三维设备红色高亮。
- 左侧告警出现。
- 对应产线变为异常。
- 右侧详情显示故障原因。
- 恢复后设备恢复 running。
- 告警消失或进入已清除状态。
- 三维颜色和产线状态恢复。
- 日志记录操作结果。

### 4.2 API/MQTT 模式

操作：

1. 启动 Mosquitto、NestJS 和 simulator。
2. 通过 MQTT 或测试控制 API 注入指定设备故障。
3. 查询 dashboard、alarms 和 digital-twin snapshot。
4. 清除同一 alarmId。
5. 再次查询并刷新浏览器。

预期：

- telemetry 更新设备状态和 metrics。
- alarm.created 生成唯一告警。
- dashboard 对应设备和产线高亮。
- alarm.cleared 使用同一 alarmId。
- 重复 created/cleared 不产生重复状态。
- 旧消息不能覆盖新状态。

## 7. 操作确认、权限和审计

### 确认要求

- 查询和产线切换：无需二次确认。
- 故障注入：必须显示目标设备、故障类型、影响和持续时间，并二次确认。
- 产线新增/编辑：确认提交。
- 停用/删除产线：显示设备、工单和告警影响清单，必须二次确认。
- 恢复设备：显示目标和当前状态，避免误恢复错误设备。
- M1 禁止提供无审批的真实设备控制。

### 最小角色

- viewer：查询和浏览。
- operator：演示故障注入和恢复。
- engineer：产线配置。
- supervisor：停用/删除等高风险确认。
- admin：权限和环境配置。

### 审计字段

- tenantId

- role
- action
- targetType
- targetId
- reason
- confirmationId
- traceId
- result
- errorCode
- createdAt
- clientVersion
