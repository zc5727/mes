# MES 智能制造运营平台里程碑计划

**项目负责人：** 赵丞  
**开发模式：** 单人全栈开发，按角色会话分工自检  
**当前版本：** 核心 MES 试点版 v1.3
**规划日期：** 2026-08-31

## 1. 项目目标

在不接入真实设备的前提下，先完成一个可重复演示、可故障注入、可恢复、可审计的四条产线 MES 核心闭环：

```text
设备模拟器 → MQTT → 后端采集 → 设备/产线状态 → 告警
    → 数字孪生看板 → 工单执行 → 策略仿真 → 结果评估
```

## 4. M1：可控演示闭环

### 交付任务

1. API 控制模式与本地仿真模式可切换。
2. 支持选择产线、设备和故障类型。
3. 支持故障注入、设备恢复和仿真重置。
4. 恢复和重置必须支持设备/产线范围，不能误伤其他产线。
5. 新增、编辑、删除产线真实调用后端接口。
6. 页面所有按钮都有加载、成功、失败和不可用状态。
7. 工厂导航支持上下滚动。
8. 数字孪生支持设备点击、三维拖拽和滚轮缩放。
9. 完成以下闭环：

```text
点击注入故障
→ 后端接收控制命令
→ 模拟器改变设备状态
→ MQTT 回传状态/告警
→ 看板高亮故障设备
→ 点击恢复设备
→ 告警清除、状态恢复
```

### M1 验收标准

- API 和本地模式均可执行故障注入与恢复。
- 一条产线发生故障时，其他产线状态不被修改。
- 页面不再出现“按钮点击无反应”。
- 后端不可用时，页面显示明确错误，不使用静态假数据掩盖失败。
- 前端 build、后端 unit/e2e、模拟器测试全部通过。
- 本地桌面程序完成重建并覆盖旧版本。

| 后端采集/API 工程师 | MQTT 控制发布、错误处理和告警回传 |
| 测试与回归工程师 | 端到端故障闭环、回归矩阵和证据 |
| 产品经理 | 验收清单、范围控制和问题汇总 |

## 5. M2：ERPNext 生产底座切换

### 交付任务

- ERPNext 版本锁定、旁路部署、adapter 和许可证清单
- PostgreSQL 作为 Integration 读模型/缓存，除非切换方案另行批准
- 工厂、车间、产线、设备、产品、工艺、班次和日历
- 设备与产线绑定关系
- 设备状态、告警和工单持久化
- 后端重启后的状态恢复
- 订单→工单→产线分配→开始→报工→完成
- 报工数量校验、重复提交和并发行为定义
- 四条产线逐条灰度、对账和回退演练

### 退出条件

- ERPNext 与现有 API 字段、状态和四线数据对账一致。
- ERPNext 不可用时可回退到 legacy，不丢失当前读模型。
- 四条产线可以并行运行工单。
- 工单状态流转和报工数据有测试证据。

## 6. M3：看板与质量能力

### 交付任务

- 数字孪生完全读取后端动态数据
- 设备、产线、告警和 OEE 实时刷新
- PDF、图片和 CAD 文件上传
- 文件版本、指纹、预览和权限
- OCR/视觉分析结果以草稿形式保存
- 人工确认后生成正式业务数据
- 点检、首件、巡检、检验和质量记录
- 质量记录关联工单、批次、设备和人员
- 维修工单、计划保养、点检异常和 MTBF/MTTR 统计
- 库存与物料由 ERPNext 主责，NestJS 做事件接入、读模型和对账
- 原料批次→工序→设备→质量→成品的正向/反向追溯

### 退出条件

- 页面不依赖静态常量展示实时状态。
- 图纸和质量记录可追溯、可复核、可重试。

## 7. M4：策略与治理

### 交付任务

- 故障后的任务转移
- 多产线负载均衡
- 物料短缺调整
- 设备维修恢复
- 订单延期风险评估
- 快照、候选方案、评分和影响评估
- 角色、数据范围和操作权限
- 高风险动作审批
- 控制操作、策略调用和结果审计

### 强制规则

- 策略默认只输出建议。
- `requiresApproval` 必须为 `true`。
- 策略引擎不能直接控制真实设备。
- 所有控制动作必须记录操作者、对象、原因、前后值、`traceId` 和结果。

| 10 | Tauri 现场冻结 | 在干净 macOS 安装签名包，验证启动、单实例、退出清理、升级回退 | `.app/.dmg` 安装记录、日志、进程/端口检查和现场签字 |

## 11. 变更规则

产品功能域、角色菜单、权限矩阵和端到端验收以 `docs/MES成熟功能域路线与端到端验收.md` 为统一入口；底座切换以 `docs/ERPNext生产底座最终切换方案.md` 为准。
最终启动、验证、故障演练、证据归档和回滚操作以 `docs/MES最终交付运行手册.md` 为准。

- 所有代码修改保持模块化、类型明确、输入校验完整。
- 不用静态数据掩盖接口故障。
- 不跨模块重复修改同一逻辑，合并前统一检查冲突。
- 每次重要代码变更后自动重建本地桌面程序覆盖旧版本。
- 未完成当前里程碑前，不扩展 SaaS、Nanobot 或复杂三维能力。
