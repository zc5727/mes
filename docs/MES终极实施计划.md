# MES 智能制造运营平台终极实施计划

**项目负责人：** 赵丞  
**开发模式：** 单人全栈开发，按角色会话并行分工、自检和回归  
**当前版本：** 核心 MES 试点版 v1.1  
**规划日期：** 2026-08-30  
**核心原则：** 先稳定生产数据链路，再扩展设备协议、质量、追溯、策略和智能能力

---

## 1. 终极目标

建设一个面向中小制造企业的主动式 MES 平台，覆盖：

```text
设备连接
  → 统一设备事件
  → 设备状态与告警
  → 生产工单与报工
  → 质量检验与批次追溯
  → 设备维护与产能分析
  → 策略仿真与审批
  → 数字孪生、专业看板和对话查询
```

第一阶段不追求“大而全”，而是先完成一个可独立运行、可重复演示、可故障注入、可恢复、可审计的四条产线试点系统。

## 4. 总体架构

```text
┌──────────────────────────────────────────────┐
│              厂长 / 主管 / 班组长 / 操作员      │
│       数字孪生 · 专业看板 · 对话查询 · 表单      │
└──────────────────────┬───────────────────────┘
                       │ REST / WebSocket
┌──────────────────────▼───────────────────────┐
│                 NestJS MES 核心                │
│ 主数据 · 工单 · 报工 · 质量 · 维护 · 策略 · 审计 │
└───────────┬──────────────────┬────────────────┘
            │                  │
     PostgreSQL           统一事件中心
            │                  │
┌───────────▼──────────────────▼────────────────┐
│              边缘接入与驱动运行时               │
│ MQTT · HTTP · Modbus · OPC UA · MTConnect       │
│ 连接管理 · 点位映射 · 重连 · 本地缓存 · 健康监控  │
└──────────────────────┬───────────────────────┘
                       │ 工业协议
┌──────────────────────▼───────────────────────┐
│ PLC · CNC · 机器人 · 视觉设备 · 仪表 · AGV       │
│ 当前以四条产线模拟器替代真实设备                 │
└──────────────────────────────────────────────┘
```

### 4.1 关键架构约束

1. NestJS 负责业务、权限、事件治理和状态，不承载大量工业轮询线程。
2. 协议驱动独立运行，通过 MQTT、HTTP 或 gRPC 与 MES 通信。
3. 旧 MQTT 模拟链路先作为适配器保留，不做破坏性迁移。
4. 原始事件先落库，再更新当前状态，最后分发到告警、工单、质量和 OEE。
5. 策略引擎默认只读和只建议，真实控制必须审批。

## 5. 统一设备事件契约

```json
{
  "messageId": "msg-001",
  "tenantId": "tenant-demo",
  "deviceId": "device-cnc-01",
  "sourceDeviceId": "cnc-01",
  "lineId": "line-cnc",
  "eventType": "telemetry",
  "occurredAt": "2026-08-30T08:00:00.000Z",
  "receivedAt": "2026-08-30T08:00:01.000Z",
  "sequence": 1001,
  "quality": "GOOD",
  "traceId": "trace-001",
  "metrics": {},
  "rawPayloadRef": "object://events/msg-001"
}
```

### 5.1 首批事件类型

```text
telemetry
alarm.created
alarm.cleared
production.completed
quality.inspected
maintenance.state_changed
connection.state_changed
material.changed
```

### 5.2 事件处理规则

- 使用 `messageId` 或 `payloadHash` 幂等。
- 使用 `occurredAt` 和 `sequence` 防止旧数据覆盖新状态。
- `receivedAt` 用于计算采集延迟。
- 非法数据进入失败记录，不得静默丢弃。
- `rawPayload` 需要大小限制、脱敏、保留周期和对象存储引用。

### M0：范围冻结（已完成）

- 固定四条产线和核心闭环。
- 明确 SaaS、Nanobot、真实 PLC 控制后置。
- 建立模拟器、后端、前端和桌面项目结构。

### M1：可控演示闭环（代码与自动化完成，人工验收待完成）

- API/本地仿真模式切换。
- 故障类型选择。
- 按产线、设备和故障类型注入。
- 设备恢复和仿真重置。
- 产线新增、编辑、删除。
- 导航滚动、设备点击、三维拖拽和缩放。
- 故障→告警→看板高亮→恢复闭环。

### M2：数据与生产底座（当前主阶段）

#### 数据底座

- PostgreSQL 连接和环境配置。
- migration、初始化数据和回滚策略。
- 工厂、车间、产线、设备、产品、工艺、班次和日历。
- `device_events`、`device_current_states`、`device_connection_events`。
- 设备状态、告警、工单和报工持久化。
- 后端重启恢复。

#### 生产执行

```text
订单
 → 工单
 → 工艺路线
 → 工序派工
 → 产线/设备执行
 → 报工
 → 质量判定
 → 完成/转序/入库
```

- 开工、暂停、恢复、取消。
- 报工数量校验。
- 重复提交和并发处理。
- 异常原因和延期风险。

**当前验收结论：进行中。** 已有数据库基础 Schema、migration、seed 和 MQTT 状态投影；业务主数据、订单、工单、报工尚未完成数据库 repository 化，因此不得宣称 M2 完成。

### M3：设备连接、看板与质量能力

#### P0 设备接入

- MQTT 通用 Payload 映射。
- HTTP/Webhook 接入。
- 连接测试、启停、健康状态和最后错误。
- 点位管理最小版。
- 当前状态和告警联动。

#### P1 协议模拟接入

- Modbus TCP 模拟服务器。
- OPC UA 模拟服务器。
- 读取、订阅、超时、重连和质量码。

#### 看板与质量

- API 动态看板。
- 产线切换、设备详情、告警刷新、OEE 刷新。
- PDF、图片、CAD 上传和版本管理。
- OCR/视觉结果草稿和人工确认。
- 首件、点检、巡检、检验、质量异常。

**当前验收结论：进行中。** 动态孪生、图纸本地演示适配、分析草稿和质量记录接口已存在并通过构建；设备连接管理、统一 HTTP/Webhook 入口、图纸/质量持久化和协议模拟器尚未形成完整运行证据。

### M4：策略、权限与治理

#### 五类策略

1. 设备故障后的任务转移。
2. 多产线负载均衡。
3. 物料短缺调整。
4. 设备维修恢复。
5. 订单延期风险评估。

每个策略必须输出：

- 候选方案
- 预计完成时间
- 延期风险
- 影响订单
- 产线负载
- 设备利用率
- 推荐原因
- `requiresApproval`

**当前验收结论：演示级完成。** 五类策略、候选评分、影响评估、角色/范围校验、审批记录和审计字段已有测试证据；生产身份认证、持久化审计和真实现场控制不在当前范围。

#### 治理要求

- 厂长、生产主管、设备主管、质量主管、班组长、操作员、审计员角色。
- 工厂、车间、产线、设备和工单数据范围。
- 控制动作二次确认。
- 审批状态机。
- 操作者、前后值、原因、审批单、`sessionId`、`traceId` 和结果审计。

### M5：桌面试点冻结

- Tauri `.app` 和 `.dmg` 实际运行。
- 双击启动后端、模拟器和前端。

## 7. 设备驱动中心路线

### 7.1 驱动优先级

```text
P0：统一事件 + MQTT + HTTP
P1：Modbus TCP + OPC UA 模拟接入
P2：MTConnect + EtherNet/IP
P3：厂商 SDK Sidecar + 真实设备现场联调
```

### 7.2 驱动能力接口

```typescript
interface DeviceDriver {
  connect(): Promise<void>;
  disconnect(): Promise<void>;
  healthCheck(): Promise<DriverHealth>;
  getCapabilities(): DriverCapabilities;
  readPoints?(points: PointDefinition[]): Promise<PointValue[]>;
  subscribePoints?(points: PointDefinition[], handler: DataHandler): Promise<void>;
  writePoints?(points: PointWrite[]): Promise<void>;
  getMetrics(): DriverMetrics;
}
```

驱动不能假设所有协议同时支持 `read`、`subscribe` 和 `write`，必须通过能力声明判断。

### 7.3 连接管理对象

```text
device_connections
device_points
device_events
device_current_states
connection_events
```

连接配置必须包含：

```text
environment: simulation | staging | production
accessMode: readonly | readwrite
```

当前强制使用：

```text
simulation + readonly
```

## 8. 权限和安全总则

### 8.1 权限判断链

```text
身份认证
 → 角色权限
 → 工厂/车间/产线/设备数据范围
 → 审批状态
 → 幂等校验
 → 执行
 → 审计
```

### 8.2 高风险动作

以下动作不能由前端按钮或智能体直接绕过：

- 真实设备启停
- 产线停线
- 批次锁定和放行
- 工单跨线转移
- 工艺参数修改
- 图纸正式发布
- 策略方案执行

### 8.3 智能秘书边界

- 可以查询授权数据。
- 可以生成分析和策略建议。
- 可以创建工单、点检和审批草稿。
- 不可以直接执行高风险生产动作。
- 每次工具调用必须携带 `userId`、`role`、`scope`、`sessionId` 和 `traceId`。

Nanobot 接入待核心 MES 稳定后再实施。

## 12. 开源复用规则

### 参考项目

- OpenMES：业务模块、生产、批次、质量、停机和追溯参考。
- MES AI：事件总线、插件、Sidecar、驱动中心和模拟器架构参考。
- Carbon：ERP/MES/QMS 和后续业务边界参考。

### 使用规则

1. 优先使用成熟协议库，不重复实现协议栈。
2. 不直接复制开源项目业务代码。
3. 固定依赖版本或 commit。
4. 建立组件、版本、许可证、商用权限和 NOTICE 清单。
5. 检查漏洞、维护活跃度、重连、超时和数据质量能力。
6. 商业部署前逐项复核许可证和再分发义务。

## 13. 关键风险与处理原则

| 风险 | 处理原则 |
|---|---|
| 设备协议范围失控 | 首期只做 MQTT/HTTP，其他协议后置 |
| 前后端状态不一致 | 统一事件、契约测试和状态机 |
| 重复/乱序数据 | messageId、sequence、occurredAt 和幂等 |
| 真实设备误操作 | 只读默认、权限、审批、审计和控制隔离 |
| 数据库重启丢失 | 原始事件、当前状态和恢复测试 |
| 视觉误判 | 草稿、置信度、人工确认和原件保留 |
| 桌面包使用旧代码 | 每次变更自动重建并覆盖旧 app |
| 单人开发超载 | P0/P1/P2/P3 分级，禁止并行扩张 |
| 开源许可证风险 | 建立许可证清单后再商用发布 |

## 15. 立即执行顺序

```text
1. PostgreSQL 持久化和恢复
2. 主数据和工单生产闭环
3. 设备连接管理最小版
4. MQTT/HTTP 统一事件中心
5. 动态数字孪生和质量表单
6. Modbus/OPC UA 模拟接入
7. 策略审批、权限和审计
8. Tauri 桌面试点冻结
9. 全量回归和运行手册
10. 再进入真实设备现场联调
```

任何阶段遇到问题，优先修复当前闭环；不得通过扩大范围、引入新框架或堆叠临时补丁逃避问题。

> **最终原则：先把生产数据链路做稳，再把设备协议做广；先让系统可恢复，再让系统主动控制；先完成核心 MES，再考虑 SaaS 和智能体扩展。**
