# MES 实施路线图

## 1. 原则

先保证可观测、可回放、可恢复，再扩展控制和智能能力。所有控制动作必须经过后端权限、确认和审计；策略默认只输出建议。演示版和生产版分离，mock/local 数据不得冒充生产数据。

## 2. 阶段状态与可验证交付物

| 阶段 | 能力 | 当前状态 | 可验证交付物 |
|---|---|---|---|
| S1 | 仿真工厂 | 已完成基础版 | simulator 固定 seed、四产线、故障注入、回放测试 |
| S2 | 基础数据 | 部分完成 | NestJS 主数据 API、设备/产线/订单/工单内存模型；PostgreSQL 迁移和恢复待完成 |
| S3 | MQTT 采集 | 部分完成 | 连接、订阅、消息校验、缓存、告警去重、重连单测和 smoke |
| S4 | 故障闭环 | 部分完成 | telemetry、alarm.created、alarm.cleared 内存链路；历史落库和重启恢复待完成 |
| S5 | 工单闭环 | API/服务已有 | 订单、工单、状态、报工接口和测试；数据库并发/恢复待完成 |
| S6 | 图纸表单 | 基础接口 | documents、quality-records API；文件上传、OCR/视觉分析待完成 |
| S7 | 策略引擎 | 候选方案已完成 | 五类风险/候选方案、评分和测试；审批执行待完成 |
| S8 | 权限审计 | 基础模型 | tenant/header、audit 基础边界；认证、细粒度授权、控制审计待完成 |
| S9 | Tauri 发布 | wrapper/macOS 包已有 | desktop smoke、app/dmg；双击服务编排、单实例、退出清理待完成 |
| S10 | 生产冻结 | 未开始 | 全量证据、签名包、回滚点、运行手册、安全清单 |

## 3. 依赖关系

S1 仿真器 → S3 MQTT 采集 → S4 故障闭环 → S2 PostgreSQL 持久化 → S5 工单闭环 → S6 图纸表单 → S7 策略仿真 → S8 权限审计 → S9 Tauri 交付 → S10 生产冻结。

主数据定义可与 MQTT 采集并行，但故障闭环的生产级通过依赖 PostgreSQL。策略可以先在内存快照上开发，但结果必须经过 S8 才能进入任何执行链路。Tauri 演示包可提前开发，生产发布依赖 S8 和 S10。

## 4. 阶段验收门槛

### S1-S4：数据与故障

- 固定 seed 可复现。
- simulator → Mosquitto → NestJS 可通。
- 重复、过期、乱序消息不回退状态。
- alarm.created 和 alarm.cleared 使用同一 alarmId。
- Broker 重启后自动恢复订阅。
- PostgreSQL 接入后后端重启仍能恢复设备和告警状态。

### S5-S6：生产和质量

- 订单→工单→报工→完成率链路通过。
- 报工不得超过计划数量，重复和并发行为确定。
- 图纸有版本、权限和原件保留。
- 表单有草稿、校验和提交状态。
- 视觉分析异步、可重试，失败可人工复核。

### S7-S8：策略和治理

- 策略结果可复现、可解释、可追踪。
- requiresApproval 必须为 true。
- 策略不直接控制设备。
- 未授权 API 调用被拒绝。
- 操作人、租户、对象、前后值、原因、确认、traceId 和结果可审计。

### S9-S10：桌面和生产

- Tauri app/dmg 可构建。
- 双击后显示服务状态，服务 ready 后进入数字孪生。
- 异常显示失败阶段、原因和建议。
- 关闭窗口清理子进程、PID 和端口。
- 生产包不含 simulator、数据库密码和 MQTT 管理凭据。
- 全部 P0 关闭，P1 有明确结论和后续版本。

## 5. 风险登记

| 风险 | 等级 | 影响 | 缓解 |
|---|---|---|---|
| MQTT 仅内存缓存 | P0 | 重启丢状态 | 接入 event/current-state |
| 数据库 schema 与 API 漂移 | P0 | 前后端数据错误 | migration 和契约测试 |
| 控制绕过权限 | P0 | 误操作设备 | 后端授权、审批、审计 |
| 演示环境连接生产 | P0 | 数据/控制事故 | 包分离、地址白名单、无生产凭据 |
| WebSocket 未闭环 | P1 | 非真正实时 | 明确 polling 降级，补 gateway |
| 图纸分析误判 | P1 | 质量风险 | 异步分析、人工复核、原件保留 |
| Tauri 子进程残留 | P1 | 端口和状态冲突 | 单实例、readiness、逆序清理 |
| 包体和高 DPI 兼容 | P2 | 用户体验 | 多分辨率、多平台验收 |

## 6. 统一命令

在仓库根目录执行：

- ./scripts/dev-up.sh --infra --mqtt
- ./scripts/dev-status.sh
- ./scripts/verify-all.sh
- node scripts/browser-smoke.mjs
- node scripts/desktop-smoke.mjs --app-dir=desktop
- ./scripts/dev-down.sh --infra

desktop-smoke 通过只表示 Tauri 结构存在，不表示双击运行通过。verify-all 不替代数据库重启、Broker 重连、浏览器人工操作和安装包验收。

## 7. 当前结论

当前版本是“可演示候选版本”。在 PostgreSQL 持久化与恢复、权限审计、Tauri 服务编排和生产安全验收完成前，不得标记为生产可用。

## 8. 下阶段全量任务（核心 MES 试点阶段）

### 8.1 目标与边界

本阶段把“可演示候选版本”推进为可重复验证、可恢复、可审计的单工厂试点版本。范围固定为一个工厂、一个车间、四条产线，覆盖设备采集、告警、工单、报工、OEE、数字孪生、图纸/表单和策略仿真。SaaS 多租户、计费、真实 PLC 闭环、自动停线、复杂视觉模型训练和复杂排产继续后置。

### 8.2 全量任务清单

| 优先级 | 任务域 | 下一阶段必须交付 |
|---|---|---|
| P0 | 交互与控制 | API/本地模式切换；故障类型选择；按设备/产线故障注入、恢复、重置；产线新增/编辑/删除；所有按钮、弹窗和错误反馈真实可用 |
| P0 | 主数据 | 工厂、车间、产线、设备、产品、工艺、班次、日历和设备绑定；统一 ID 映射 |
| P0 | 采集闭环 | MQTT 校验、幂等、乱序/延迟处理、缓存、告警去重、重连；`alarm.created`/`alarm.cleared` 闭环 |
| P0 | 生产执行 | 订单→工单→产线分配→开始→报工→检验→完成；暂停、恢复、取消、异常原因和延期风险 |
| P0 | 数字孪生 | API 动态数据、产线切换、设备详情、告警刷新、OEE/进度；导航滚动、三维拖拽、缩放、点击 |
| P1 | 图纸/表单/视觉 | PDF/图片/CAD 上传、版本、预览、指纹；OCR/视觉草稿、人工确认；点检、检验、质量记录和附件审计 |
| P0 | 策略引擎 | 故障转移、负载均衡、物料短缺、维修恢复、延期风险；快照、候选方案、评分、影响评估和可解释原因 |
| P0 | 权限审计 | 厂长/班组长/设备员/操作员角色；数据范围；审批；控制动作记录操作者、对象、前后值、原因、traceId 和结果 |
| P0 | 桌面发布 | app/dmg 实际运行；双击编排服务、ready 探测、单实例、关闭清理、缩放/拖拽/滚轮、失败提示和回滚 |
| P0 | 测试交付 | 单元、接口、集成、故障、恢复、安装包和人工验收；备份恢复、运行手册、接口文档和版本记录 |

### 8.3 里程碑

| 里程碑 | 工期 | 退出条件 |
|---|---:|---|
| M1 可控演示闭环 | 3～5 个工作日 | 所有无效按钮修复；故障注入→告警→看板高亮→恢复通过 |
| M2 数据与生产底座 | 5～8 个工作日 | PostgreSQL 持久化、主数据、重启恢复、工单状态机和报工校验通过 |
| M3 看板与质量能力 | 5～8 个工作日 | 看板不依赖静态数据；图纸/表单/点检/质量记录可追溯 |
| M4 策略与治理 | 5～8 个工作日 | 五类策略可复现；只输出建议；审批、权限、审计通过 |
| M5 桌面试点冻结 | 4～6 个工作日 | app/dmg、启动/停止/重启/清理和全量回归通过；P0 全部关闭 |

### 8.4 立即执行顺序

1. 建立按钮—接口—状态更新—错误反馈映射表，清零当前无效按钮。
2. 完成 API 模式下按设备/产线范围的故障恢复和重置，禁止全局误伤。
3. 将主数据和设备/告警状态落到 PostgreSQL，补齐迁移、初始化和恢复。
4. 每次变更自动执行本地桌面重建，覆盖旧 app 后再人工验证。
5. 完成上述闭环后，再进入图纸/表单、策略审批和生产冻结，不提前扩展 SaaS 或 Nanobot。
