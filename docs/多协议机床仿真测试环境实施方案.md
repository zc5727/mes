# 多协议机床仿真测试环境实施方案

## 1. 目标

在真实机床接入前，建立一套协议级、行为级和安全级预验证环境，验证设备数据读取、实时订阅、启动/停止/暂停/复位/急停、设备专属故障、随机故障、通信中断、重连、MES 实时展示、设备增删、3D 模型同步、权限、审计和回放。

本系统不是演示性质的随机数据生成器，而是**真实设备接入前的仿真测试环境**。

---

## 2. 页面职责调整

### 2.1 仿真控制台：唯一的仿真管理入口

仿真设备选择、增加、删除、启动、停止、故障注入、随机故障、场景编排和平台接入配置全部放到独立的仿真控制台。

访问地址：

```text
http://127.0.0.1:5174
```

### 2.2 孪生页面：只负责接入后的运行展示

孪生页面删除原有的本地仿真选择框和本地仿真控制内容，包括：

- `API 控制 / 本地仿真` 选择框；
- 本地故障注入选择框；
- 本地仿真恢复按钮；
- 本地仿真速度控制；
- 本地模拟启动、停止和故障入口；
- 任何让用户误以为可以在孪生页面配置仿真设备的控件。

孪生页面只保留：

- 接入设备的实时状态；
- 设备、产线、报警和通信状态；
- 3D 场景；
- 设备接入中心；
- 真实接入设备的权限控制操作；
- 连接详情、数据质量和通信日志。

孪生页面不维护独立的模拟设备列表。设备列表和 3D 场景都以 MES 后端设备注册表为唯一事实来源。

## 5. 设备 Profile

机械类型、控制器和通信协议必须分开定义：

```text
机械类型：三轴铣床 / 五轴加工中心 / 数控车床 / 工业机器人
控制器：SINUMERIK / FANUC / Mitsubishi / HEIDENHAIN
协议：OPC UA / FOCAS / MTConnect / Modbus TCP / MQTT
```

初始 Profile：

```text
generic-cnc-opcua
siemens-sinumerik-opcua
fanuc-cnc-mtconnect
generic-cnc-modbus
```

每个 Profile 必须定义：

- 数据点和数据类型；
- NodeID 或寄存器地址；
- 读写权限；
- 采样周期；
- 时间戳和质量码；
- 控制方法；
- 状态转换；
- 报警编码；
- 故障目录；
- 3D 模型映射。

未根据真实厂商文档确认的数据，不得标记为真实厂商兼容。

## 7. 控制命令和状态机

标准命令：

```text
Start
Stop
Pause
Resume
Reset
EmergencyStop
AcknowledgeAlarm
LoadProgram
SetMode
```

禁止直接写入 `IsRunning = true`。必须调用控制方法并经过状态机：

```text
READY → STARTING → RUNNING
RUNNING → STOPPING → STOPPED
RUNNING → EMERGENCY_STOP
EMERGENCY_STOP → Reset() → READY
```

每个命令必须记录：

```json
{
  "commandId": "cmd-001",
  "deviceId": "cnc-001",
  "command": "Start",
  "requestedBy": "operator-001",
  "requestedAt": "2026-08-31T10:00:00.000Z",
  "accepted": true,
  "result": "ACCEPTED",
  "previousState": "READY",
  "targetState": "STARTING"
}
```

## 8. 协议仿真

### OPC UA

每台设备使用独立 endpoint：

```text
opc.tcp://127.0.0.1:4841/device/cnc-001
opc.tcp://127.0.0.1:4842/device/cnc-002
```

必须支持 Browse、Read、Subscription、DataValue、SourceTimestamp、ServerTimestamp、Quality、StatusCode、认证、权限拒绝、断线重连和方法调用。

节点结构：

```text
Objects/Machine
├── Identification
├── Status
├── Spindle
├── Axes
├── Program
├── Alarms
└── Methods
    ├── Start
    ├── Stop
    ├── Pause
    ├── Reset
    └── EmergencyStop
```

### Modbus TCP

每个寄存器必须定义地址、名称、功能码、数据类型、字节序、缩放系数、读写权限和非法值处理。

### MTConnect

支持：

```text
/probe
/current
/sample
```

模拟 availability、execution、controllerMode、program、pathFeedrate、spindleSpeed、alarm、asset 和 tool。

### FOCAS

FOCAS 不能用普通 TCP 服务冒充。需要 Windows、FANUC FOCAS SDK、真实 API 和错误码验证。Mac 阶段只实现 Adapter Contract，不宣称真实 FOCAS 兼容。


- 设置初始状态和仿真倍率；
- 手动故障注入；
- 随机故障；
- 场景保存、导出和回放。

## 10. 故障系统

通用故障：

```text
COMMUNICATION_LOSS
CONNECTION_TIMEOUT
SUBSCRIPTION_LOST
BAD_QUALITY
STALE_DATA
DUPLICATED_COMMAND
INVALID_COMMAND
COMMAND_TIMEOUT
DEVICE_OFFLINE
```

CNC 故障：

```text
SPINDLE_OVERLOAD
SPINDLE_OVERHEAT
AXIS_OVERTRAVEL
SERVO_FOLLOWING_ERROR
TOOL_LIFE_EXPIRED
TOOL_BROKEN
COOLANT_LOW
LUBRICATION_LOW
HYDRAULIC_PRESSURE_LOW
AIR_PRESSURE_LOW
SAFETY_DOOR_OPEN
EMERGENCY_STOP
PROGRAM_SYNTAX_ERROR
WORKPIECE_CLAMP_FAILED
```

不同设备只能使用其 Profile 声明的故障目录。

随机故障必须支持：

- 固定随机种子；
- 故障概率；
- 最短运行时间；
- 最大故障数量；
- 持续时间；
- 自动恢复规则；
- 事件导出；
- 场景回放。

相同种子、相同输入和相同版本必须产生一致的故障序列。

## 13. 设备与 3D 模型同步

设备注册表是唯一事实来源：

```text
设备注册表
├── 仿真控制台
├── MES 后端
└── 孪生 3D 页面
```

### 新增设备

```text
控制台新增设备
→ 创建设备注册记录
→ 分配 deviceId
→ 启动协议服务
→ 发布 device.created
→ MES 接收事件
→ 孪生页面接收事件
→ 加载对应 3D 模型
→ 开始实时状态更新
```

### 删除设备

```text
控制台删除设备
→ 停止协议服务
→ 发布 device.removed
→ MES 停止采集
→ 孪生页面删除设备
→ DeviceManager 销毁 Mesh
→ 设备列表同步删除
→ 审计记录保留
```

事件类型：

```text
device.created
device.updated
device.removed
device.telemetry
device.state.changed
device.alarm.created
device.alarm.cleared
connection.state.changed
```

3D 绑定使用 Profile 的模型标识：

```ts
interface DeviceVisualBinding {
  deviceId: string;
  lineId: string;
  modelKey: string;
  position: [number, number, number];
  rotation: [number, number, number];
  scale: number;
}
```

禁止按设备 ID 写死模型。新增和删除事件必须同时更新设备列表、详情、统计和 3D 场景。

## 14. 实时数据链路

```text
协议仿真器
→ OPC UA Subscription / MTConnect / Modbus Poll
→ MES 设备接入层
→ 规范化设备遥测
→ 状态缓存和持久化
→ SSE/WebSocket
→ 孪生页面
→ 看板和 3D 状态刷新
```

每条数据必须校验数据时间、数据质量、通信状态、设备状态、超时和重复数据。通信异常时不得继续把旧数据显示为最新数据。

## 16. 验收场景

### 新增设备

```text
控制台新增设备
→ 协议服务启动
→ MES 接入成功
→ 孪生列表出现
→ 3D 模型出现
→ 实时数据刷新
```

### 删除设备

```text
控制台删除设备
→ 协议服务停止
→ MES 停止采集
→ 孪生列表删除
→ 3D 模型销毁
→ 审计记录保留
```

### 启动停止

```text
READY → Start → STARTING → RUNNING
RUNNING → Stop → STOPPING → STOPPED
```

### 故障注入

```text
注入主轴过载
→ 产生报警
→ 状态变为 FAULT
→ 3D 模型变红
→ 启动命令被拒绝
→ Reset
→ 恢复 READY
```

### 通信中断

```text
停止协议服务
→ 订阅断开
→ MES 标记 DEGRADED/OFFLINE
→ 孪生页面显示通信异常
→ 旧数据不再标记为最新
→ 服务恢复后自动重连
```

## 17. 实施顺序

1. 从孪生页面移除原有本地仿真选择框和控制区；
2. 创建独立仿真控制台 `:5174`；
3. 建立设备注册中心和 Profile 管理；
4. 实现 OPC UA 可浏览节点、订阅和控制方法；
5. 实现设备状态机、专属故障和随机故障；
6. 实现平台地址配置和连接测试；
7. 实现孪生页面接入中心；
8. 实现 `device.created` / `device.removed` 事件；
9. 实现 3D 模型动态增删和状态同步；
10. 完成断线、超时、权限、审计和回放测试；
11. 根据真实设备资料逐项校验 Profile。

---

## 18. 强制约束

- 仿真控制只在独立仿真控制台执行；
- 孪生页面不再出现旧的本地仿真选择框；
- 孪生页面不维护独立模拟设备状态；
- 不使用玩具式随机数据替代协议测试；
- 不伪造 Siemens 或 FANUC 的真实 NodeID；
- 不把 MQTT 控制当成 OPC UA 控制；
- 不允许前端直接修改设备状态；
- 所有控制命令经过后端、权限和审计；
- 故障状态下不得无条件启动；
- 通信异常时不得继续显示设备在线；
- 删除设备必须同步停止协议服务并销毁 3D 模型；
- 新增设备必须同步进入设备列表和 3D 场景；
- 所有随机故障必须可复现；
- 所有协议适配器必须有独立测试；
- 真实设备接入时只替换 Adapter，不修改 MES 核心业务。
