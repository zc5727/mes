## 3. 质量门禁

每个阶段必须同时满足：

1. `git diff --check` 无错误，模块边界无越界改动。
2. 后端 build、unit/e2e、模拟器检查、前端 build 通过。
3. 失败路径有明确 HTTP/UI 错误，不以静态数据掩盖失败。
4. 四条产线范围隔离，重复消息/重复报工/重复点击具备幂等语义。
5. 所有高风险控制只生成建议或进入审批，不直达真实设备。
6. 形成命令、输出、时间和版本号组成的验收证据。

## 4. 当前已确认的范围冲突

- `docs/阶段8-数据持久化设计与迁移计划.md` 的旧版状态已与实现不符；该文档必须明确数据库写入按配置启用，且未迁移模块仍保留内存 fallback。
- Tauri `desktop-smoke` 只验证工程结构，不能代替双击启动、服务编排和退出清理验收。
- `scripts/verify-desktop-release.sh --app=PATH --dmg=PATH --notary-profile=NAME` 缺少真实 artifact、Apple 工具或凭据时必须返回 `BLOCKED`，不能标记为通过。
- 当前前端/后端 build 通过不等于图纸文件流、细粒度权限和浏览器 DOM 交互通过。
- 本地模拟数据、API 数据和数据库生产数据必须在 UI 标识 `dataSource`，禁止混用。

## 5. 执行顺序

1. M2 先落地 Prisma 运行时、migration、seed 和 repository；不先改 M3/M4 UI。
2. 用 M2 持久化重跑 MQTT 故障闭环、工单报工和重启恢复。
3. M3 以冻结的数字孪生实时契约替换页面静态字段，再做图纸/表单最小可追溯闭环。
4. M4 将策略结果、审批和审计串成只读建议闭环；未经审批禁止控制调用。
5. M5 最后接入服务编排和安装包，执行全量回归后冻结版本。
