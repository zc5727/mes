# MES 最终回归门禁矩阵

## 1. 目的

本门禁用于没有真实工厂设备时，验证四条产线仿真、设备接入契约、告警闭环、权限边界、数据库迁移和前端交互契约。Mock 只用于单元测试；真实 PostgreSQL、MQTT、对象存储和运行时服务必须单独取得真实运行证据。

## 2. 分层门禁

| 层级 | 命令 | 覆盖范围 | 判定 |
| --- | --- | --- | --- |
| 代码级 | `./scripts/verify-all.sh` | 后端 unit/E2E/build、数据库 schema、模拟器、simulator-ui、数字孪生前端、交互契约、Tauri 结构 | 可作为 CI 门禁 |
| 不可用依赖 | `./scripts/verify-runtime-unavailable.sh` | Compose 缺失或真实依赖不可用时的 fail-closed 行为 | 必须输出 `BLOCKED` 并返回 2 |
| 真实运行 | `./scripts/verify-runtime.sh` | PostgreSQL/MQTT/MinIO readiness、迁移、回滚、API/MQTT、故障、四线、重启、SSE、清理 | 必须真实运行；不可用不得算通过 |
| 现场交互 | `node scripts/frontend-browser-smoke.mjs` | 浏览器点击、产线切换、滚轮、拖拽、滚动和表单 | 需要 Playwright 或现场浏览器 |

## 3. 当前覆盖重点

- 设备 Profile：协议模板、未验证标识、数据点、控制能力和未知 Profile 拒绝。
- MTConnect：synthetic probe/sample、canonical telemetry、端口复用和无厂商兼容性伪装。
- 设备启停：连接测试、启动、健康、停止、状态事件、目标设备和租户隔离。
- 故障链路：telemetry → MQTT → cache → alarm → dashboard → 恢复；重复告警不得重复生成。
- 四线场景：CNC、装配、焊接、视觉检测并行运行，状态和策略快照不可串线。
- 权限：缺失身份、只读角色控制拒绝、Agent 服务账号角色限制、租户/范围越权拒绝。
- 前端：刷新/重连、产线切换、设备选择、产线 CRUD、业务表单入口、禁用按钮、三维旋转/缩放/点击契约。

## 4. 失败诊断

真实运行脚本会检查 `3000/5173/5174/5432/1883/9000` 端口占用，并为每次运行使用独立 Compose 项目和临时卷。失败时保留命令输出；不得用旧进程、Mock 或结构 smoke 替代真实服务证据。

```bash
cd /Users/a1/Documents/ChatGPT/mes
./scripts/verify-all.sh
./scripts/verify-runtime.sh
node scripts/simulator-ui-contract-smoke.mjs
node scripts/simulator-ui-smoke.mjs
```

## 5. 不得误判

- Tauri 结构 smoke 不等于 `.app/.dmg` 双击、安装卸载、签名、公证和单实例实机通过。
- 前端源码契约不等于真实浏览器手势通过。
- `verify-runtime-unavailable.sh` 的通过含义是“不可用时正确阻断”，不是业务运行通过。
