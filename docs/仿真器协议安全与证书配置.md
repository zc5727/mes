# 仿真器协议安全与证书配置

本文只描述 `/Users/a1/Documents/ChatGPT/mes/simulator` 当前可执行的 synthetic contract。它用于真实设备接入前的协议、错误和权限边界验证，不代表真实厂商兼容，也不提供真实设备证书或 NodeID。

## 能力矩阵

| 协议 | 当前入口 | TLS | 认证 | 证书配置 | 权限 |
| --- | --- | --- | --- | --- | --- |
| MQTT | 现有 `MessagePublisher` | `mqtts://` URL scheme | URL credentials 交给 Broker | simulator CLI 不暴露自定义 CA/client cert/key | 由 Broker ACL 决定；连接初始超时默认 2s |
| HTTP | synthetic `POST /events` | 不实现 HTTPS | `none` 或 Bearer | 不支持 | 只收 telemetry，不收控制命令 |
| Modbus TCP | synthetic FC03 server/client | plain TCP，不适用 | 不实现 | 不适用 | 只读 holding registers |
| OPC UA | synthetic read-only server/client | 不实现安全通道 | anonymous only | 不实现证书校验/证书登录 | 只读合成节点 |
| MTConnect | synthetic `/probe`、`/current`、`/sample` | plain HTTP | 不实现 | 不实现 | 只读 |

矩阵对应运行时代码 `src/protocols/capabilities.ts`，由 `protocol-matrix.test.ts` 和 `capabilities.test.ts` 校验。任何未列出的协议必须 fail-closed，不得自动降级成 MQTT、HTTP 或其他协议。

## 端点配置

HTTP 端点是本地遥测接收契约：

```ts
parseHttpEndpoint({
  protocol: "http",
  host: "127.0.0.1",
  port: 16102,
  path: "/events",
  authentication: "bearer",
  bearerToken: "local-demo-token",
  tls: false,
});
```

它只接受 `POST`、`application/json` 和 `event=device.telemetry`。错误方法返回 `405`，错误内容类型返回 `415`，未授权返回 `401`，非法遥测返回 `422`，请求体超限返回 `413`。`tls: true` 会直接拒绝配置，不会静默改用明文。

OPC UA synthetic 端点的安全参数必须明确保持在以下范围：

```ts
parseOpcUaSecurity({
  securityMode: "None",
  securityPolicy: "None",
  authentication: "anonymous",
});
```

其他 SecurityMode、SecurityPolicy、用户名/密码或证书认证会被拒绝。当前 endpoint 使用 `node-opcua` 的 self-signed/None 本地测试配置，严格证书校验、权限拒绝、订阅和方法调用均未实现。

## MQTT 证书说明

以下命令只验证 MQTT 客户端按 URL 使用 TLS 和 Broker credentials 的入口：

```bash
MQTT_URL=mqtts://user:password@127.0.0.1:8883 \
  npm run dev --prefix simulator -- --seed 20260828 --once
```

当前 simulator CLI 不提供 `CA`、客户端证书或私钥文件参数，因此不能宣称完成双向 TLS 或自定义 CA 验证。真实环境必须在独立 MQTT adapter 中明确配置证书、校验 hostname、Broker ACL 和连接失败行为，再进行验收；不得把 stdout fallback 当作 MQTT 已连接。

`MqttPublisher.connect()` 会在默认 2 秒内未建立连接时失败；连接建立后的断线由 MQTT 客户端按 1 秒重连周期处理，但未连接期间的 publish/subscribe 会 fail-closed，不排队伪造成功。

## 验证命令

```bash
npm run check --prefix simulator
npm run protocols:smoke --prefix simulator
npm run build --prefix simulator
node --test simulator/dist/protocols/protocol-matrix.test.js simulator/dist/protocols/capabilities.test.js
```

OPC UA 测试可能输出 node-opcua 的 self-signed SAN/endpoint warning；这些 warning 不等于证书认证通过，测试仍必须以明确的读数、错误和关闭结果为准。
