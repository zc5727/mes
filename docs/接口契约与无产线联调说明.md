# MES 接口契约与无产线联调说明

## 1. 目的

本文件定义演示阶段前后端共用的数据边界。没有真实 PLC、数采网关或产线网络时，先用固定 mock 快照验证页面、状态映射和接口联调；接入真实设备时只替换数据源，不改变页面消费的数据结构。

当前后端只实现健康检查接口，业务接口先按契约预留，避免在数据模型未冻结前过早耦合数据库和设备协议。

## 2. 环境约定

| 变量 | 作用 | 示例 |
|---|---|---|
| `NODE_ENV` | 运行环境 | `development` |
| `PORT` | HTTP 端口 | `3000` |
| `DATABASE_URL` | PostgreSQL 连接串 | `postgresql://...` |
| `MQTT_URL` | MQTT Broker 地址 | `mqtt://localhost:1883` |
| `MINIO_ENDPOINT` / `MINIO_PORT` | 对象存储地址 | `localhost` / `9000` |
| `MINIO_ACCESS_KEY` / `MINIO_SECRET_KEY` | 本地开发凭据 | 仅放在未跟踪的 `.env` |

校验示例配置：

```bash
cd backend
npm run verify:env
# 本地启动前额外确认 backend/.env 存在
npm run verify:env -- --check-local
```

`.env` 不提交到 Git；团队共享配置只通过 `.env.example` 和部署平台的密钥管理注入。

## 3. REST 契约（业务接口预留）

统一前缀：`/api/v1`

### `GET /health`（已实现）

```json
{
  "status": "ok",
  "service": "mes-saas-backend",
  "timestamp": "2026-08-28T08:00:00.000Z"
}
```

### `GET /health/components`（已实现）

返回部署诊断所需的数据库和 MQTT 状态。该接口不返回 Broker URL、用户名、密码或 Token，适合桌面启动页和运维探针使用。

```json
{
  "service": "mes-saas-backend",
  "timestamp": "2026-09-01T00:00:00.000Z",
  "database": { "enabled": true, "status": "ready" },
  "mqtt": {
    "enabled": true,
    "connected": true,
    "state": "connected",
    "lastHeartbeatAt": "2026-09-01T00:00:00.000Z",
    "lastError": null,
    "lastErrorCode": null
  }
}
```

### `GET /factories/{factoryId}/snapshot`（已实现）

返回 `backend/test/fixtures/factory-snapshot.json` 同结构的工厂快照。演示阶段使用 fixture；生产阶段由设备采集、MES 业务库和策略服务拼装。

### `GET /production-lines?factoryId={factoryId}`（已实现）

返回四条或多条产线的基础状态列表。`id` 是稳定业务标识，不使用数组下标作为前端 key。

## 4. 实时事件契约

WebSocket 或 MQTT 网关向前端转发统一信封：

```json
{
  "type": "device:update",
  "payload": {
    "id": "DEV-04",
    "lineId": "LINE-02",
    "status": "warning",
    "temperature": 61.2,
    "power": 38.6,
    "occurredAt": "2026-08-28T08:00:00.000Z"
  }
}
```

当前允许的事件类型：

- `snapshot`：首次连接或重新连接后的完整快照
- `device:update`：单台设备状态变化
- `alarm`：异常或告警产生
- `log`：可审计的运行日志

事件处理必须幂等：同一 `id` 的设备更新覆盖旧值，不能重复追加设备；异常与日志保留服务端生成的唯一 ID。

## 5. 无真实产线联调流程

```bash
cd backend
npm ci
npm run verify:env
npm run verify:mock
npm run build
npm run smoke:api
```

`verify:mock` 会检查：

- 快照恰好包含四条演示产线；
- 产线 ID 唯一且设备都绑定到已存在的产线；
- 状态枚举合法；
- 完成数不超过计划数，OEE 和完成率在 0～100 之间。

这套流程不连接 PostgreSQL、MQTT、MinIO，也不需要真实设备即可完成前后端基础验收。前端数字孪生的现有 `WebSocketService` 继续作为浏览器端动态 mock；服务端 fixture 用于接口契约和回归校验。
