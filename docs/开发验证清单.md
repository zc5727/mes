# MES 开发验证清单

## 每次提交前

```bash
cd /Users/a1/Documents/ChatGPT/mes/backend
npm run verify:env
npm run verify:mock
npm test -- --runInBand
npm run test:e2e -- --runInBand
npm run build

cd /Users/a1/Documents/ChatGPT/mes/third_party/threejs-factory-demo
npm run build
```

## 无产线环境验收

1. 不启动 Docker 依赖，执行后端 `verify:env`、`verify:mock`、`build`。
2. 执行 `smoke:api`，确认 `/api/v1/health` 可用。
3. 启动前端，确认四条产线均可切换，数字孪生设备状态能够刷新。
4. 关闭后端或断开网络，确认前端 mock 仍可演示；恢复真实接口时不得把 mock 数据和生产凭据提交到仓库。

## 当前边界

- 业务 REST、设备 MQTT、策略执行和数据库尚未实现，当前测试只覆盖已实现的健康接口与 mock 契约。
- `backend/.env` 是本机文件，严禁提交；新增敏感配置必须同步更新 `.env.example` 的变量名，不要写入真实值。
- 真实产线接入前，需要补充协议适配器、消息重放、故障注入、权限和审计测试。
