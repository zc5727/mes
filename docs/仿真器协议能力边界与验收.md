# 仿真器协议能力边界与验收

## 结论

本文件区分“已实现链路”和“synthetic contract”。后者只用于本地联调、数据契约和故障测试，不代表真实设备、真实厂商驱动或真实地址兼容。

| 协议/传输 | 当前能力 | 写入 | 订阅/推送 | 事实边界 |
| --- | --- | --- | --- | --- |
| MQTT | 现有 `MessagePublisher`、遥测主题和控制主题 | 支持 simulator/twin 控制命令 | 支持 MQTT Broker 订阅 | 未配置 `MQTT_URL` 时 CLI 明确降级为 stdout，不应视为 MQTT 已连接 |
| HTTP | synthetic `/events` telemetry ingest；严格校验方法、JSON、鉴权和请求体 | 不支持控制写入 | 不支持 | 仅 plain HTTP；可选 Bearer；不实现 HTTPS/证书；不是厂商设备接口 |
| WebSocket | 未实现 | 不支持 | 不支持 | simulator 没有 WebSocket server/client；前端实时链路不能据此宣称已验证 |
| Modbus TCP | synthetic FC03 holding-register server/client | 禁止 | 不支持 | 非法功能码和非法寄存器请求失败关闭；不模拟写寄存器 |
| OPC UA | synthetic read-only server/client | 禁止 | 未实现 | `SecurityMode=None`、`SecurityPolicy=None`、anonymous only；不实现证书校验、完整 Browse/Subscription/Method/Auth |
| MTConnect | synthetic `/probe`、`/current`、`/sample` | 禁止 | 不支持 | 使用 `sim-*` data item ID；不是 MTConnect 真实设备 Agent |
| FOCAS | 未实现 | 不支持 | 不支持 | 需要 Windows、FANUC SDK 和真实 API 验证 |

## 固定种子与回放

固定 `--seed` 后，设备随机产出、故障操作序列、网络丢包/重复和 replay frame 应保持一致。`FactorySimulator` 的 replay 文档包含：

- `version`、`tenantId`、`intervalMs`、`timeScale`、设备 `seed`、网络 `networkSeed`；
- 原始 `scenario` 事件；
- 按序号排列的消息帧；暂停/停止期间实际发出的告警和网络延迟消息也必须保留。

可执行验收：

```bash
cd /Users/a1/Documents/ChatGPT/mes/simulator
npm run dev -- --seed 20260828 --time-scale 1 --scenario examples/fault-replay-scenario.json
```

验收点：第 2 个仿真秒出现 `alarm.created`，`cnc-01` 和 `line-cnc` 进入 `FAULT` 且 OEE 受影响；第 6 个仿真秒出现 `alarm.cleared` 并恢复。程序内可使用 `exportScenario()`、`loadScenarioDocument()` 和 `exportReplay()` 完成保存与回放。

跨进程回放使用 `node dist/index.js --replay-file /absolute/path/replay.json`。程序会先校验 replay JSON，再按原始帧顺序发布 `frames[].messages`，不重新推进产线，也不执行文件中的控制命令；非法版本、seed、时间戳、帧序号、消息结构或场景命令必须拒绝。

## 状态机边界

当前 simulator 对外稳定状态是 `RUNNING`、`IDLE`、`WARNING`、`STOPPED`、`FAULT`、`OFFLINE`。`start`/`stop`/`pause`/`resume`/`reset` 通过命令处理器进入状态变更；故障优先级会覆盖手动启停，通信中断会进入 `OFFLINE`，清除最后一个故障后才允许恢复。实施方案中更细的 `READY`、`STARTING`、`STOPPING`、`EMERGENCY_STOP`、`MAINTENANCE` 状态和异步方法调用尚未由 simulator 宣称实现，不能在验收中当作已验证能力。

## Fail-closed 规则

1. 未知协议、非法端口、非法数据类型、非法状态码和非法故障码必须抛错，不能自动映射到 MQTT、HTTP 或其他协议。
2. HTTP 仅允许 synthetic `/events` 遥测入口；WebSocket 不是协议 server；没有监听器就不能报告“已连接”。
3. synthetic OPC UA/MTConnect/Modbus 只输出 canonical telemetry，不接受设备写入命令。
4. MQTT stdout fallback 只用于无 Broker 的本地 demo；生产联调应设置 `MQTT_URL` 并确认 Broker 连接成功。
5. Modbus/MTConnect/OPC UA endpoint 的 `start()` 和 `close()` 必须幂等；协议 smoke 在成功、异常和端口冲突后都清理本地 endpoint，端口被占用时必须保留原监听者并返回错误。
6. Modbus MBAP 协议标识、事务标识、unit、功能码、字节数和寄存器数不匹配时拒绝帧；OPC UA 非 Good status code 和 MTConnect 缺失/非法 XML 字段不能进入 canonical telemetry。
7. Siemens、FANUC 等 Profile 是测试标签，未经真实资料校验不得升级为 vendor-compatible。

## TLS、认证、权限和证书配置矩阵

当前矩阵是仿真器的运行时声明，不是对真实设备能力的推断：

| 协议 | TLS | 认证 | 证书 | 权限边界 |
| --- | --- | --- | --- | --- |
| MQTT | `mqtts://` URL scheme 可用 | URL 中的用户名/密码交给 Broker | 当前 CLI 不暴露自定义 CA/client cert/key | Broker ACL 决定发布、订阅和控制权限 |
| HTTP | 未实现 HTTPS | `none` 或 Bearer | 不支持证书配置 | 仅接受 telemetry POST，不接受控制命令 |
| Modbus TCP | 不适用，plain TCP | 未实现 | 不适用 | 仅 synthetic FC03 读寄存器 |
| OPC UA | 未实现安全通道 | anonymous only | 不实现证书校验或证书登录 | synthetic 节点只读 |
| MTConnect | 未实现 HTTPS | 未实现 | 不实现 | `/probe`、`/current`、`/sample` 只读 |

证书配置约束：

- `simulator` 当前不读取或生成用户提供的 CA、客户端证书、私钥和厂商证书；不能把 `tls=true` 当作已启用 TLS。
- MQTT 使用 `mqtts://` 只表示由 MQTT 客户端按 URL 建立 TLS；自定义证书文件仍未由 simulator CLI 暴露，需在真实接入 adapter 中单独配置和验收。
- OPC UA 的 self-signed/None endpoint 仅用于 synthetic contract；严格证书校验、用户名/密码、证书登录和权限拒绝属于未实现能力，必须显式标记为未验证。
- HTTP、Modbus TCP、MTConnect 的 TLS/证书选项会 fail-closed，不会静默降级为明文后报告“安全连接”。

配置示例（仅说明能力边界，不包含真实厂商地址）：

```ts
parseHttpEndpoint({
  protocol: "http", host: "127.0.0.1", port: 16102,
  authentication: "bearer", bearerToken: "local-demo-token",
  tls: false,
});
parseOpcUaSecurity({
  securityMode: "None", securityPolicy: "None", authentication: "anonymous",
});
```

## 测试门禁

```bash
npm run check --prefix simulator
npm run protocols:smoke --prefix simulator
npm run protocols:smoke:mtconnect --prefix simulator
```

测试覆盖 canonical MQTT/HTTP adapter、Modbus 非法帧和异常响应、OPC UA 读取与生命周期、MTConnect 三个端点与生命周期、未知协议拒绝、synthetic 写入拒绝、固定种子/网络种子重放和端口清理。

统一协议矩阵和安全声明测试：

```bash
npm run build --prefix simulator
node --test simulator/dist/protocols/protocol-matrix.test.js simulator/dist/protocols/capabilities.test.js
```

## 明确缺口

- simulator 本身没有 WebSocket 实现，WebSocket/SSE 需由后端实时层另行验收；
- OPC UA 目前是只读最小入口，Browse/Subscription/Method/认证/权限拒绝和证书校验仍未在 simulator 侧实现；
- Modbus 目前只覆盖 FC03 读寄存器，写入、完整地址表和异常码矩阵未实现；
- MTConnect 目前是 XML 合同模拟，不包含真实 Agent 的序列号、资产、工具和生产级流式语义；
- Profile 已驱动配置和协议选择，但完整的控制台设备编排、设备注册事件和真实连接测试仍属于后续集成范围。
