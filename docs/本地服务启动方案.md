# MES 本地服务启动方案

## 服务与端口

| 服务 | 目录/容器 | 端口 | 健康检查 |
|---|---|---:|---|
| Backend | `backend` | 3000 | `GET /api/v1/health` |
| Frontend | `third_party/threejs-factory-demo` | 5173 | HTTP 入口 |
| Simulator UI | `simulator-ui` | 5174 | HTTP 入口 |
| Simulator | `simulator` | 无固定端口 | PID 和日志 |
| MQTT | `mes-mqtt` | 1883 | TCP 连接 |
| PostgreSQL | `mes-postgres` | 5432 | TCP 连接 |
| MinIO | `mes-minio` | 9000 | 容器状态 |

## 一键启动

在仓库根目录执行：

```bash
./scripts/dev-up.sh --infra --mqtt
```

桌面启动器直接调用统一命令：

```bash
./scripts/desktop.sh start --infra --mqtt
./scripts/desktop.sh run
./scripts/desktop.sh status
./scripts/desktop.sh stop --infra
```

实际启动顺序：

```text
基础设施 → MQTT/PostgreSQL readiness → Backend → Backend health → Frontend → Simulator UI → Simulator
```

`dev-up.sh`/`desktop-runtime.sh` 会将日志写入 `.runtime/logs/`，并在托管启动后执行基础设施、Backend health/readiness 和前端可用性检查；“进程已启动”仍不等于完整业务链路已验收。真实设备协议、WebSocket 推送、桌面 GUI 联动和生产恢复演练仍需单独验收。

在当前 macOS/Codex 非交互执行器中，执行器可能在启动命令返回后清理其子进程，
因此不能用一次非交互 shell 调用可靠证明 `dev-up.sh` 的进程脱离能力。当前不将
该场景标记为通过；需要在 launchd、Docker Compose 或其他明确的进程监管器下单独
验证进程存活。该验证也不替代 `./scripts/dev-up.sh --infra --mqtt` 的真实
PostgreSQL/MQTT 验收。

Docker Compose 不可用时，脚本会尝试使用 Docker Engine 创建或启动 `mes-postgres`、`mes-mqtt`、`mes-minio` 容器。
桌面开发使用 `desktop.sh run` 或 `cd desktop && npm run dev`，该前台进程负责持有会话锁；窗口/进程退出时会清理 Backend、Simulator 子进程。

## 状态和停止

```bash
./scripts/dev-status.sh
./scripts/dev-down.sh
./scripts/dev-down.sh --infra
```

`dev-down.sh` 默认只停止应用进程；传入 `--infra` 才停止本地基础设施容器。
启动过程中任一 readiness 检查失败时，启动脚本返回非零退出码，并清理本次已启动的应用进程。
`dev-status.sh` 在任一健康检查失败时返回非零退出码，桌面启动器可据此阻止进入演示页面；发现失效 PID 文件会自动清理。
Tauri 已启用单实例插件；重复启动会被拦截并将已有主窗口置前。

## 不启动 MQTT 的开发模式

```bash
./scripts/dev-up.sh
```

此模式下 Backend 使用 HTTP-only 配置，Simulator 不连接 Broker，适合只调试 REST 和前端页面。

## 环境变量

```bash
MQTT_URL=mqtt://localhost:1883
MES_TENANT_ID=tenant-demo
```

## 故障诊断

```bash
./scripts/dev-status.sh
tail -f .runtime/logs/backend.log
docker ps
docker logs --tail=100 mes-mqtt
curl -fsS http://localhost:3000/api/v1/health
```

常见故障：

- Backend health 超时：查看 `.runtime/logs/backend.log`，确认 3000 端口未被占用。
- MQTT 不通：确认 `MQTT_URL`、1883 端口和 `mes-mqtt` 容器状态。
- Simulator 退出：查看 `.runtime/logs/simulator.log`，确认 MQTT 地址和租户参数。
