# 多协议仿真环境架构审查

审查基线：`docs/多协议机床仿真测试环境实施方案.md`、当前工作树及
`simulator/src`。本轮只做边界核对和低风险修正，不修改数字孪生业务页面。

## 一、当前落地清单

| 范围 | 当前状态 | 结论 |
| --- | --- | --- |
| MQTT | 已有 publisher 和后端 ingestion/control 链路 | 可做本地事件链路验证；尚不是 TLS/ACL/真实 Broker 验收 |
| HTTP | `adaptHttpEvent` 合同适配器 | 未打开 HTTP 仿真服务，不能宣称 HTTP 设备接入已实现 |
| Modbus TCP | 独立端点、FC03、固定寄存器布局、响应校验 | 只读 synthetic contract；尚无完整 Profile 地址表和控制写入 |
| OPC UA | 独立端点、Read、DataValue 基础读取和断线重连 | 只读 synthetic contract；无 Browse/Subscription/Method/认证权限闭环 |
| MTConnect | `/probe`、`/current`、`/sample` 和规范化适配 | synthetic contract；数据项不是厂商设备声明 |
| Profile | 协议、机械、控制器和故障目录已分离 | 未验证厂商 NodeID/寄存器，必须保持未声明兼容 |
| 状态机/故障 | 四产线状态、故障注入、通信异常和固定种子回放已有测试 | 可做行为回归，仍需端到端控制台到 MES 验收 |
| 回放 | 场景 JSON、故障事件和 replay frame 元数据已有实现 | 需补版本锁定、导入校验和跨进程验收 |
| 权限/审计 | API key、租户边界、`x-user-role` 能力门禁和 PostgreSQL 审计队列 | 需启用 required 模式并完成真实数据库重启/多实例验收 |
| NestJS/PostgreSQL | NestJS 模块和 Prisma schema 可构建/校验 | 当前 E2E 使用测试应用；生产数据库迁移和恢复演练仍需运行环境 |

## 二、风险与冲突

1. 实施方案要求 OPC UA 的认证、权限拒绝、订阅和方法调用；当前实现明确是
   anonymous/None 的只读 synthetic server。若不补齐，禁止标记为 Siemens 或
   通用真实设备兼容。
2. 实施方案要求 Modbus 完整寄存器元数据和控制语义；当前 FC03 固定十个寄存器
   只能验证报文边界和规范化读取，不能验证真实设备地址或写入安全性。
3. MQTT 当前 capability 标记为 `IMPLEMENTED`，但 TLS、ACL、重连、重复消息和
   Broker 持久化没有形成验收门禁；HTTP 仅是 adapter，二者不能在文档中混称为
   完整协议服务。
4. `AuditService` 保留内存读模型，但 API 请求会在响应前 flush 审计事件和审批到
   PostgreSQL；只有 `MES_AUDIT_PERSISTENCE_REQUIRED=true` 才会在持久化失败时
   fail-closed。未启用该模式仍只是演示级降级。
5. 策略运行本体仍通过既有 `StrategyPersistenceService` 保存治理快照；审批和审计
   已独立落表，但三者尚未处于同一 PostgreSQL 事务。required 模式下不能把“审批
   已落库”扩大解释为“策略运行快照也已原子落库”。
6. `x-user-role` 是路由最小权限门禁，不是可信身份来源。策略和 Agent 业务上下文
   仍读取既有 `x-role`，接入网关时必须同时映射两者，直到统一认证上下文。
7. 审查期间并行工作树曾短暂处于 `DashboardService` 修改中间态；同步完成后已复核
   backend build 和全量单测通过。本轮提交不包含该并行核心业务改动。

## 三、必须修改项（按优先级）

### P0：接入真实设备前必须完成

- 为每个 Profile 建立可审计的版本、证据来源、数据点类型、读写权限和声明状态；
  未验证 Profile 只能标记 synthetic/contract。
- 控制命令统一经过后端状态机、权限、审批（如策略要求）和审计；协议层保持
  只读适配，不允许绕过 MES 直接写状态。
- 在 required 模式下完成 PostgreSQL 迁移、重启恢复、租户隔离、哈希链和多实例
  一致性验证；当前代码已覆盖最小事件/审批表和 API 响应前 flush。后续需把策略
  运行快照与审批状态收敛到同一事务。

### P1：完成协议环境闭环前必须完成

- OPC UA 补 Browse、Subscription、Source/Server timestamp、quality/status、
  认证失败、权限拒绝、方法调用和断线重连测试。
- Modbus 按 Profile 实现地址表、字节序、缩放、非法值和异常响应测试；控制写入
  必须有独立 capability 和 fail-closed 测试。
- MQTT 补 TLS/ACL、重连、重复/过期消息、坏质量和 Broker 不可用测试；HTTP 若要
  作为协议服务，必须实现受校验的 HTTP endpoint，否则保留 adapter-only 标识。
- 完成控制台设备增删、Profile 选择、协议端点编排、连接测试和审计的真实浏览器
  验收；数字孪生页面只消费 MES 注册表，不新增本地仿真控制。
- 恢复并固定 backend lint 配置（当前 ESLint 9 缺少 flat config），再纳入 CI 门禁。

## 四、本轮低风险修正

- 所有 mutating controller 已显式标注 `RequireCapability`；未标注的变更路由
  fail-closed。
- `x-user-role` 仅作用于写入/控制/管理路由；GET、HEAD、OPTIONS 即使所在控制器
  有管理能力标注也保持只读兼容。
- 修复协议清理路径中吞掉 OPC UA、Modbus 和 MTConnect 错误的问题，关闭失败会
  显式失败；协议能力仍按 synthetic/contract 状态暴露。

## 五、验证与阻塞

已验证：协议适配器和协议桥测试覆盖身份、计数不变量、坏响应、端口隔离和重连；
角色门禁单测覆盖缺少标注、缺少角色、viewer 越权和读接口兼容。

当前阻塞：生产 PostgreSQL、真实 MQTT Broker、OPC UA 安全模式和厂商协议资料未
在本地环境完成验收；backend lint 仍需补 ESLint 9 flat config 后才能纳入 CI。
