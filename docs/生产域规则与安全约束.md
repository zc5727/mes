# MES 生产域规则与安全约束

> 版本：v0.1  
> 责任域：生产业务规则、安全、审批和审计  
> 适用范围：订单、工单、报工、质量、图纸、表单  
> 本文只定义领域契约，不替代后端实现。

## 1. 统一规则

1. 所有状态变更必须经过后端状态机校验。
2. 客户端按钮隐藏不等于权限控制，越权请求必须由后端拒绝。
3. 所有写操作必须携带 tenantId、operatorId、requestId 和 occurredAt。
4. 生产数据按租户、工厂、产线、设备逐级隔离。
5. 已产生业务影响的数据不得物理删除，使用取消、作废或归档。
6. 所有审批、确认、拒绝和执行结果必须可审计。
7. 质量、图纸和表单必须绑定订单或工单。
8. 图纸版本和表单版本发布后不可原地修改，只能创建新版本。

## 2. 订单状态机

DRAFT → RELEASED → IN_PROGRESS → COMPLETED

DRAFT、RELEASED、IN_PROGRESS 均可在满足条件时进入 CANCELLED。

状态规则：

| 状态 | 可执行操作 | 禁止操作 |
|---|---|---|
| DRAFT | 编辑订单、提交审核 | 开工、报工 |
| RELEASED | 创建工单、分配产线 | 修改核心产品和数量 |
| IN_PROGRESS | 查看进度、处理异常 | 任意减少计划量 |
| COMPLETED | 查询、归档 | 修改数量、删除 |
| CANCELLED | 查询、归档 | 开工、报工、恢复 |

订单完成条件：

- 关联工单全部完成，或订单完成数量达到计划数量。
- 存在未处理严重质量异常时，不得自动完成。
- 取消必须填写原因并经过生产主管审批。

## 3. 工单状态机

DRAFT → RELEASED → RUNNING → PAUSED → RUNNING

DRAFT、RELEASED、RUNNING、PAUSED 可按权限进入 CANCELLED；RUNNING 可进入 COMPLETED。

现有 API 状态值保持：

- draft
- released
- in_progress
- paused
- completed
- cancelled

强制校验：

- plannedQty > 0。
- completedQty >= 0 且不得超过 plannedQty。
- 报工数量不得超过工单剩余数量。
- 完成数量不得倒退。
- 工单产线必须属于当前租户。
- 设备报工时，设备必须属于工单产线。
- 每次状态迁移写入状态历史。
- paused 和 cancelled 必须填写原因。
- completed 只能在 completedQty = plannedQty 时产生。

## 4. 报工规则

报工至少包含：

- workOrderId
- quantity
- goodQty
- defectQty
- deviceId（设备采集报工时必填）
- sourceTraceId
- operatorId
- requestId

强制规则：

- quantity > 0。
- goodQty >= 0。
- defectQty >= 0。
- goodQty + defectQty = quantity。
- quantity 不得超过工单剩余数量。
- sourceTraceId 必须幂等。
- 重复请求不得重复累计产量。
- 报工成功后更新工单和订单汇总。
- 报工失败不得部分写入。
- 人工修改已提交报工必须走更正流程，不得覆盖原记录。

## 5. 质量状态机

DRAFT → SUBMITTED → INSPECTING → PASSED

INSPECTING 可进入 FAILED；FAILED 可进入 REWORK 或 SCRAPPED。

质量规则：

- 质量记录必须绑定工单和产品。
- 检验项目、标准、实测值和判定结果必须可追溯。
- FAILED 必须填写缺陷原因和缺陷分类。
- REWORK 必须生成返工任务或关联返工工单。
- SCRAPPED 必须经过质量主管确认。
- 严重质量异常未关闭时，禁止工单自动 COMPLETED。
- 质量记录提交后只能追加更正记录。

## 6. 图纸规则

状态机：

DRAFT → REVIEWING → APPROVED → RELEASED → OBSOLETE

REVIEWING 可进入 REJECTED，REJECTED 返回 DRAFT。

规则：

- 图纸必须绑定产品、订单或工单。
- 每个产品只能有一个当前 RELEASED 版本。
- 图纸必须记录版本号、文件校验值和上传人。
- APPROVED 前不能用于生产。
- RELEASED 后禁止覆盖文件。
- 替换图纸必须生成新版本。
- 审核人与上传人原则上不得为同一人。
- 过期图纸不得出现在默认生产界面。
- 图纸下载、预览和导出必须审计。
- 图像解析结果只能作为辅助信息，不能自动修改生产参数。

## 7. 表单规则

状态机：

DRAFT → SUBMITTED → REVIEWING → APPROVED → ARCHIVED

REVIEWING 可进入 REJECTED，REJECTED 返回 DRAFT。

规则：

- 模板必须有版本号。
- 发布后的模板不可直接修改。
- 表单实例必须绑定订单、工单、产线或设备。
- 必填字段未完成不得提交。
- 数值字段必须校验范围和单位。
- 关键字段修改必须保留修改前后值。
- 表单提交后不可由普通操作员删除。
- 审核退回必须填写原因。
- AI 或自动填报结果必须标记为系统建议，并由人工确认。

## 9. 审批和操作确认

必须审批：

- 订单发布和取消。
- 工单取消。
- 工单计划数量下调。
- 跨产线转移。
- 严重质量异常放行。
- 图纸正式发布。
- 表单模板发布。
- 策略方案执行。
- 真实设备启停或参数变更。

必须二次确认：

- 暂停正在运行的产线。
- 取消未完成工单。
- 提交报工更正。
- 发布新图纸版本。
- 批次报废。
- 执行批量策略动作。

确认页必须显示目标对象、当前状态、变更后状态、影响订单、影响数量、风险提示和操作原因。

## 10. 审计字段

所有生产写操作至少记录：

auditId、tenantId、factoryId、lineId、deviceId、resourceType、resourceId、action、operatorId、operatorRole、requestId、sessionId、clientType、clientVersion、beforeState、afterState、reason、approvalId、result、errorCode、occurredAt。

报工额外记录：

quantity、goodQty、defectQty、sourceTraceId、sourceType。

图纸额外记录：

documentId、version、fileHash、fileSize、reviewerId、releaseAt。

表单额外记录：

templateId、templateVersion、instanceId、changedFields、attachmentHashes。

质量额外记录：

inspectionId、defectCode、inspectionResult、disposition、reviewerId。

## 11. 越权拒绝规则

后端必须拒绝：

- 无 tenantId 的请求。
- 跨租户访问订单、工单、设备、图纸或表单。
- 不具备产线权限的操作员提交其他产线报工。
- 普通用户发布图纸或审核质量。
- 未审批执行取消、报废或设备控制。
- 状态机不允许的状态跳转。
- 工单完成数量超过计划数量。
- 暂停工单期间报工。
- 使用过期图纸生产。
- 修改已提交报工而没有更正流程。
- 重复 sourceTraceId 造成重复累计。
- 客户端直接连接数据库、MQTT 控制主题或 PLC。
- 通过伪造角色字段提升权限。

建议错误码：

AUTH_REQUIRED、TENANT_SCOPE_DENIED、RESOURCE_SCOPE_DENIED、ROLE_FORBIDDEN、INVALID_STATE_TRANSITION、APPROVAL_REQUIRED、CONFIRMATION_REQUIRED、QUANTITY_EXCEEDED、DUPLICATE_TRACE、DOCUMENT_VERSION_INVALID、QUALITY_HOLD、DEVICE_CONTROL_FORBIDDEN。

## 12. 当前后端缺口清单

1. 统一角色和权限守卫。
2. 订单、工单状态历史持久化。
3. sourceTraceId 数据库唯一约束。
4. 报工设备与工单产线的后端关联校验。
5. 质量记录和质量 HOLD 机制。
6. 图纸元数据、版本审批和文件校验值。
7. 表单模板、实例和审核流程。
8. 审批单、审批节点和二次确认记录。
9. 统一审计事件模型。
10. 数据库事务、行锁或乐观锁。
11. 图纸、表单、质量 DTO 契约测试。
12. 真实设备控制服务的独立权限边界。

## 13. 验收项

### 状态机

- 非法状态跳转被拒绝。
- 终态订单和工单不可继续写入。
- 暂停、取消、退回必须有原因。
- 完工满足数量和质量条件。

### 权限

- 用户只能访问授权租户、工厂、产线和设备。
- 修改客户端请求不能越权。
- 普通操作员不能审核质量、发布图纸或执行策略。
- 厂长可以发起申请，但不能绕过审批直控设备。

### 数据完整性

- 报工数量、合格数、缺陷数满足约束。
- 重复请求不重复累计。
- 报工与订单、工单、设备可追溯。
- 图纸和表单可追溯版本。
- 质量异常可以阻止工单完成。

### 设备安全

- 客户端不直连 PLC、MQTT 控制主题或数据库。
- 策略仿真不改变真实生产状态。
- 真实控制经过后端审批、确认、执行和结果记录。
