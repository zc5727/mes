# MES 设备接入、驱动中心与连接平台实施计划

## 1. 目标与边界

本计划的目标是让现有 MES 从“模拟器 MQTT 接入”演进为可通过边缘驱动接入真实 PLC、CNC、机器人、视觉设备、仪表和 AGV 的设备连接平台。

核心原则：

1. **优先复用成熟开源项目，不重复实现工业协议栈。**
2. MES 主服务负责设备台账、配置、权限、事件治理和业务状态；协议驱动运行在独立的边缘运行时。
3. 所有厂商数据先转换为统一设备事件，再进入生产、质量、维护和追溯业务。
4. 第一阶段只做可靠采集和只读闭环，真实设备写入必须独立授权、审批和审计。
5. 保持当前四条产线模拟器可运行，模拟器与真实设备使用同一套统一事件契约。

## 2. 开源复用策略

### 2.1 参考项目

| 项目 | 用途 | 采用方式 |
|---|---|---|
| [OpenMES](https://github.com/Mes-Open/OpenMes) | 生产、批次、质量、停机、追溯、审计业务参考 | 参考模块划分和数据流程，不直接复制业务代码 |
| [MES AI](https://github.com/point85/mes-ai) | 插件、事件总线、驱动 Sidecar、仿真器架构参考 | 优先评估其插件/Sidecar设计及可复用组件 |
| [Carbon](https://github.com/crbnos/carbon) | ERP + MES + QMS 扩展参考 | 作为后续 ERP/QMS 边界参考 |

### 2.2 协议组件选型原则

不得为了“自己可控”重新实现 OPC UA、Modbus、MQTT 或 MTConnect 协议。候选开源组件必须经过：

- 许可证兼容性审查；
- 最近提交、Issue、Release 和维护活跃度审查；
- 断线重连、超时、订阅、质量码和异常处理测试；
- 连接凭据、证书和日志脱敏审查；
- 压力、长时间运行和设备模拟测试；
- 商业部署、修改、再分发义务确认。

协议优先级：

```text
MQTT / HTTP → Modbus TCP → OPC UA → MTConnect → 厂商 SDK Sidecar
```

## 3. 目标架构

```text
真实设备 / PLC / CNC / 机器人 / 视觉 / AGV
                    ↓
             边缘驱动中心
   MQTT | HTTP | Modbus | OPC UA | MTConnect | SDK
                    ↓
          统一设备事件与消息总线
                    ↓
       MES 接入层：校验、幂等、落库、状态
                    ↓
  生产执行 | 质量 | 维护 | 追溯 | OEE | 数字孪生
                    ↓
              看板、API、智能问数
```

NestJS 不直接承载大量工业连接和轮询任务。驱动中心以独立进程或容器运行，通过 MQTT、HTTP 或 gRPC 与 MES 后端通信。对于必须使用 Java、C++、C# 或 Go SDK 的设备，采用 Sidecar，不把厂商 SDK 引入核心服务。

## 4. 模块规划

### 4.1 设备连接平台

- 设备注册、型号、协议、工厂/产线/工位归属；
- 连接参数、采集周期、超时、重连策略；
- 凭据引用和证书管理；
- 连接测试、启停采集、在线状态；
- 驱动版本、能力声明和兼容型号；
- 连接日志、采集延迟、解析失败和丢包统计。

### 4.2 驱动中心

- MQTT Driver：Topic、QoS、认证、JSON/CSV/二进制 Payload 映射；
- HTTP Driver：Webhook、签名校验、批量上报、重试；
- Modbus Driver：TCP/RTU、寄存器、功能码、类型、字节序、缩放；
- OPC UA Driver：Endpoint、证书、Namespace、NodeId、订阅、质量码；
- MTConnect Driver：Agent、Streams、Assets、设备状态映射；
- 厂商 SDK Sidecar：CNC、机器人、历史数据库和特殊控制器。

### 4.3 点位和数据映射

统一维护：

```text
sourcePoint → dataType → scale/offset → unit → quality → targetField
```

必须支持数值、布尔、字符串、枚举、时间、数组、结构体和原始报文保留。

### 4.4 统一事件中心

第一版事件类型：

```text
telemetry
alarm.created
alarm.cleared
production.completed
quality.inspected
maintenance.state_changed
connection.state_changed
```

统一事件至少包含：`messageId`、`tenantId`、`deviceId`、`sourceDeviceId`、`lineId`、`eventType`、`occurredAt`、`receivedAt`、`sequence`、`quality`、`metrics`、`rawPayload`。

## 5. 需要补充的业务模块

按优先级分为：

### P0：真实数据闭环

- 设备连接管理；
- MQTT 通用 Payload 映射；
- HTTP/Webhook 接入；
- Modbus TCP 采集；
- OPC UA 采集；
- 统一事件模型；
- 原始事件表、当前状态表、连接事件表；
- 断线、重连、超时、幂等和数据质量；
- 后端 MQTT 到 WebSocket 的实时推送。

### P1：MES 核心执行

- 产品和物料主数据；
- BOM；
- 工艺路线、工序和版本；
- 工位、设备能力和作业指导书；
- 派工、开工、暂停、完工、报工、返工、转序；
- WIP、批次、序列号和条码追溯。

### P2：质量与维护

- IQC/IPQC/OQC；
- 质量特性、抽检规则、不良代码；
- 视觉检测结果和图片关联；
- NCR、CAPA、质量放行；
- 点检、保养、维修工单、备件；
- MTBF、MTTR 和设备健康评分。

### P3：计划与外部系统

- 班次、日历、有限产能排程；
- 换型时间、人员和物料约束；
- ERP、WMS、PLM、BI 集成；
- 成本、库存、采购和财务扩展。

## 6. 对现有代码的改造路线

### 第 0 步：冻结契约和基线

- 保留当前模拟器作为契约测试源；
- 统一 `deviceId`、`sourceDeviceId`、`lineId`；
- 明确时间戳、质量码、序列号和幂等键；
- 清理“协议枚举已支持但驱动未实现”的表述。

### 第 1 步：建立接入核心

新增建议目录：

```text
backend/src/device-ingestion/
backend/src/driver-center/
backend/src/connection-management/
backend/src/point-mapping/
backend/src/events/
```

先把当前 `/backend/src/mqtt` 中的模拟器专用解析逻辑迁移到 MQTT Driver，并增加通用映射层；不先删除现有内存缓存，数据库 current-state 稳定后再切换读模型。

### 第 2 步：边缘运行时

建立独立的 `device-drivers` 工作区，包含：

```text
driver-sdk
mqtt-driver
http-driver
modbus-driver
opcua-driver
mtconnect-driver
native-sdk-sidecar
```

每个驱动必须提供：`connect`、`disconnect`、`healthCheck`、`read`、`subscribe`、`metrics` 和明确异常类型。

### 第 3 步：持久化和业务分发

增加：

```text
device_events
device_current_states
device_connection_events
device_point_values
production_events
quality_events
```

合法事件先落原始事件，再更新当前状态，最后分发到告警、报工、质量、OEE 和数字孪生模块。

## 7. 验收标准

### 协议验收

- 每个驱动有真实协议模拟器测试；
- 能处理断线、重连、超时、重复消息、乱序消息和非法数据；
- 不同厂商字段可映射到同一统一事件；
- 设备重启后 current-state 可恢复；
- 原始报文可通过 traceId 查询。

### MES 业务验收

```text
设备 telemetry
 → 当前状态
 → 设备告警
 → 生产计数
 → 工单报工
 → 质量结果
 → 批次追溯
 → 看板与历史报表
```

### 安全验收

- 租户隔离和设备权限校验；
- 凭据不进入日志和原始事件展示；
- 采集和控制通道分离；
- 真实设备默认只读；
- 所有配置修改、驱动启停和控制操作可审计。

## 8. 近期执行清单

1. 完成 GitHub 项目、协议库和许可证清单；
2. 确定 MQTT、Modbus、OPC UA 三类首批驱动的开源实现；
3. 冻结统一设备事件 JSON Schema；
4. 新建设备连接、点位映射和驱动健康 API；
5. 将现有模拟器接入新事件中心；
6. 增加 MQTT 通用 Payload 映射；
7. 接入 Modbus TCP 模拟设备；
8. 接入 OPC UA 模拟服务器；
9. 完成事件落库、current-state 和重启恢复；
10. 再开始真实厂商设备现场联调。

## 9. 当前不做的事情

- 不直接重写工业协议栈；
- 不一开始覆盖所有厂商和所有型号；
- 不在 NestJS 主进程中堆叠大量驱动线程；
- 不先做 SaaS 计费、多租户商业化和复杂云交付；
- 不在没有审批、权限和审计的情况下开放真实设备写入。
