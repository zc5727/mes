# MES 核心闭环回归执行手册

## 目标

在没有真实设备的情况下，验证：

```text
模拟器 → MQTT/JSON → 后端采集 → 设备/产线/告警 → MES API → 数字孪生数据契约 → 策略仿真
```

## 快速验证命令

### 后端

```bash
cd backend
npm run build
npm test -- --runInBand
npm run test:e2e -- --runInBand
```

覆盖：健康检查、设备消息契约、MQTT 解析与去重、告警、Dashboard、工单、策略输入和只读 nanobot 工具契约。

其中 `test/core-loop.unit.spec.ts` 使用固定消息和内存 MQTT 客户端，重复验证“仿真器消息 → MQTT 采集 → 告警/Dashboard API”闭环，不依赖真实设备或 Broker：

```bash
npm test -- --runInBand core-loop.unit.spec.ts
```

### 模拟器

```bash
cd simulator
npm test
```

覆盖：固定随机种子、产量/OEE、四条产线、故障注入、物料短缺、质量异常、暂停恢复、断线/重复/延迟消息、策略回放。

### 前端

```bash
cd third_party/threejs-factory-demo
npm run build
```

覆盖：Vue 类型检查、数字孪生构建和后端响应契约编译。

## 联调启动

先启动 Mosquitto，再启动后端和模拟器：

```bash
cd backend
docker compose up -d mosquitto

MQTT_ENABLED=true MQTT_URL=mqtt://localhost:1883 npm run start:dev
```

另一个终端：

```bash
cd simulator
npm run dev -- --mqtt mqtt://localhost:1883 --seed 20260828 --time-scale 5
```

第三个终端：

```bash
cd third_party/threejs-factory-demo
npm run dev
```

## 故障验收场景

```bash
npm run dev -- \
  --mqtt mqtt://localhost:1883 \
  --seed 20260828 \
  --fault line-cnc:cnc-01:OVERHEAT
```

预期链路：

```text
alarm.created
→ 后端设备状态变为 FAULT
→ 活动告警可查询
→ 产线状态变为 FAULT
→ Dashboard 数据变化
→ 数字孪生设备高亮
→ 策略仿真返回候选方案
```

## 遗留边界

- MQTT 实联需要本地 Mosquitto 正常运行。
- 当前状态中心仍以内存为主，重启后不保留历史数据。
- 数字孪生已接入 MES API，但完整 MQTT 实时链路仍需在 Mosquitto 启动后执行场景验收。
- 策略只生成仿真建议，不执行真实设备控制。
- nanobot 当前只有只读工具契约，不包含智能秘书实现。
